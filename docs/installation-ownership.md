# 설치 소유권과 제거

`make install`은 의존성 설치·macOS 앱 빌드·사용자 설치를 수행하고 `make uninstall`은 설치 소유 기록을 확인한 뒤 해당 항목만 제거한다. `make install-plan`, `make uninstall-plan`은 사용자 설정을 바꾸지 않고 대상을 출력한다. ZIP에도 각각의 설치·제거 명령이 포함된다.

## 단일 요청 스킬

`skills/work/SKILL.md` 하나를 배포한다. 스킬은 카탈로그의 책임 경계·입력 스키마를 읽고 사용자가 요청한 결과와 동작을 최대 24개 작업의 `prompt/steps` 계획으로 분할한다. 원문 인용·산출물 식별자·실제 자료 의존성을 붙여 `orchestrate`로 한 번 제출한다. 실행 서비스가 계획 검증·순서·동시성·`codex exec`/`claude -p` 실행·검증·수정·취소·재개를 소유한다. 업무별 스킬이나 스킬 안의 별도 실행기를 만들지 않는다. 단일 `run`의 자연어 분류는 제한된 호환 경로이며 복합 요청은 [구조화 계획](task-orchestration.md)을 사용한다.

설치된 스킬의 `scripts/harness`는 해당 설치의 Node·CLI·데이터 디렉터리에 고정된 실행 도우미다. 경로는 셸 인자로 인용하고 프롬프트는 JSON 파일로 전달한다. 내부 worker의 재귀 제출은 기존 CLI 경계로 차단한다. 설치가 유료 모델 사용이나 Jira 등의 외부 쓰기를 자동 승인하지 않는다.

| 연결 | 용도 |
|---|---|
| `~/.claude/skills/work` | Claude 개인 스킬 |
| `~/.agents/skills/work` | Codex 공식 개인 스킬 탐색 |
| `~/.codex/worklog/skills/work` | 같은 원본을 가리키는 Codex 설정 디렉터리의 참조 |

세 연결은 설치 버전의 같은 스킬 디렉터리를 가리킨다. 기존 `CLAUDE.md`·`AGENTS.md`는 수정하지 않는다. 경로 선택은 [Codex 공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)와 [Claude 공식 스킬 문서](https://code.claude.com/docs/en/skills)를 따른다. 조직 정책이나 도구 환경이 스킬 로딩을 제한하면 자동 활성화를 가정하지 않는다.

## 소유 근거

`~/Library/Application Support/WorkLog/installation.json`에 형식 버전, 설치 UUID, 홈, 고정 실행 버전, 훅별 정확한 객체와 그룹 조건, 심링크 경로·대상·파일 식별자, LaunchAgent 정의·실행 인자, 배포 파일별 해시·권한을 기록한다. 외부에 전달하거나 모델에게 출력시킬 데이터가 아니다.

훅 명령에는 `WORKLOG_INSTALL_ID`가 포함된다. 표준 훅 JSON에 도구가 알지 못하는 소유자 필드를 삽입하지 않는다. 설정의 원본 백업은 `install-backups/<설치 UUID>/`에 보존하지만, 제거할 때 전체 백업으로 현재 설정을 덮어쓰지 않는다.

| 항목 | 제거 조건 | 보존 조건 |
|---|---|---|
| 개별 훅 | 설치한 명령·옵션·그룹 조건이 정확히 일치하는 항목이 하나 있음 | 명령/옵션 수정, 중복, 잘못된 JSON, 설정 심링크 교체 |
| 지시문 심링크 | 설치 위치·대상·기록된 파일 식별자가 일치 | 다른 대상, 일반 파일/디렉터리로 교체, 상위 디렉터리 심링크 |
| LaunchAgent | 소유 기록의 정의와 파일 해시 일치 | 변경된 정의 또는 다른 프로그램이 같은 서비스 이름을 사용 |
| 앱·고정 실행 파일 | 기록한 파일과 일치하고 추가된 사용자 파일 없음 | 수정·추가된 파일이 있으면 그 디렉터리 전체 보존 |
| 업무 데이터·자격증명 | 제거 대상 아님 | SQLite, 산출물, 로그, 백업, Keychain 앱 자격증명과 토큰 유지 |

동일 그룹에 나중에 추가한 다른 훅은 보존한다. 설정 파일 자체나 `.claude`·`.codex`·`.agents` 폴더를 삭제하지 않는다. 심링크 대상 디렉터리를 따라 재귀 삭제하지 않으며 설치 파일도 기록된 항목만 하나씩 확인해 제거한다. 수정된 훅이나 연결이 남으면 그것이 참조하는 실행 파일을 유지한다.

## 중단과 재실행

설치와 제거는 같은 로컬 잠금을 사용한다. 소유 기록은 공유 설정 변경 전에 저장한다. 설치 도중 서비스 등록 등이 실패해도 기록으로 제거를 재개할 수 있다. 파일 복사가 일부만 끝난 경우 기록된 파일의 일치 여부를 확인하며 모르는 파일을 추정해 제거하지 않는다.

동일한 정상 설치를 다시 설치하면 `already_installed`를 반환하고 훅을 중복 추가하지 않는다. 기존 설치의 변경·미완료 상태는 명확히 보고한다. 이미 제거한 기록은 같은 이름의 새 파일에 대한 삭제 권한으로 재사용하지 않는다. 소유 기록 없는 과거 버전은 `unmanaged`로 남기며 이름 검색으로 정리하지 않는다.

활성화된 서비스는 설치한 Label·실행 인자가 일치할 때만 `launchctl bootout`한다. 서비스 제거가 비동기로 완료될 수 있으므로 최대 10초 동안 재조회하며 소유 관계와 종료를 확인한다. 서비스와 기록된 실행 프로세스의 종료를 확인하지 못하면 파일을 제거하지 않는다. 변경·누락된 기록으로 종료 권한을 추정하지 않는다.

CLI는 완료/이미 제거/미설치에 0, 보존된 충돌·미관리 설치에 2, 잘못된 인자·기록 등 실행 실패에 1을 반환한다. 설치·제거 후 기존 에이전트 세션이 이미 읽은 지시문까지 회수했다고 주장하지 않는다.

## 검증

`tests/e2e/install.test.mjs`는 임시 홈에서 실제 파일·설정·심링크와 CLI를 사용한다. 정상 제거, 재설치·재제거, 같은 그룹의 사용자 훅, 훅 편집·중복·손상, 링크 교체, 파일/상위 경로 심링크, 변경된 앱, 기록 누락·경로 변조, 설치 중단 복구, 같은 서비스 이름의 다른 프로그램, 데이터 보존을 검증한다.

`make install`/`make uninstall`의 CLI 연결을 검사하며 설치된 요청 스킬의 실행 도우미로 단일 자연어 요청 → 내부 업무 분류 → Codex 프로토콜 대역 → 산출물 전달과 실제 수집 훅 → work item을 검증한다. 구조화 계획의 CLI·의존 실행·복구는 `tests/e2e/cli-orchestration.test.mjs`, `plans.test.mjs`, `plan-recovery.test.mjs`에서 별도로 확인한다. 이 검증이 실제 에이전트의 스킬 해석·분할 품질까지 입증하지는 않는다. 모델 대역을 사용하므로 유료 호출은 없다. 사용자 홈의 실제 훅·LaunchAgent·Keychain은 변경하지 않는다. 서비스 등록·종료 시나리오는 launchctl 대역으로 소유 검사를 검증하며 실제 로그인 재시작 시험과 구분한다.

## 앱 종료와 다시 열기

메뉴 막대의 `WorkLog 종료`는 제거 명령이 아니다. 설치 파일·훅·스킬·업무 데이터를 유지하고 관리 서비스를 중지한다. 실행 서비스에는 내부 관리 작업만 취소하도록 요청한다. 사용자 요청으로 실행 중이거나 대기 중인 본 작업과 DAG의 후속 작업은 유지하며, 모두 끝난 뒤 실행 서비스도 정상 종료한다. 외부 Codex·Claude 세션은 종료 대상이 아니다. 앱이 닫힌 동안 훅 이벤트는 기존 로컬 스풀에 남고, 다음 실행에서 수집한다.

`runtime`의 LaunchAgent는 비정상 종료 시 재시작하되 정상 종료 시에는 재시작하지 않는다. 앱을 다시 열면 소유가 확인된 서비스만 등록·시작하고, 아직 진행 중인 실행 서비스에는 종료 대기 해제를 요청한다. 시작·종료는 설치/제거와 같은 잠금으로 직렬화한다. 종료 실패 시 앱을 유지해 오류를 보여 주며 종료됐다고 표시하지 않는다. 개발용 번들은 실제 사용자 설치의 서비스를 제어하지 않는다.

`tests/e2e/install.test.mjs`는 지연된 launchd 제거, 종료 시간 초과 후 안전한 재시도, 사용자 작업이 있는 종료와 재연결, 정상 종료 후 휴면 서비스 시작을 추가로 검증한다. `make uninstall`은 명시적인 설치 제거이므로 앱 종료와 달리 모든 설치 소유 서비스를 종료한 뒤 파일을 제거한다.
