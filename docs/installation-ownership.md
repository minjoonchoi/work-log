# 설치 소유권과 에이전트 연결

`make install`은 의존성 설치·임시 macOS 앱 빌드·사용자 설치를 수행한다. 설치 대상은 현재 사용자의 `~/Applications/WorkLog.app`, WorkLog 전용 LaunchAgent 3개와 고정 실행 파일이다. Claude/Codex의 설정·훅·스킬 연결은 설치하지 않는다. GUI의 **연결 설정**에서 엔진별로 명시적으로 연결한다. `make uninstall`은 설치 소유 기록을 확인해 앱·서비스와 이후 GUI에서 만든 WorkLog 연결을 제거한다. `make install-plan`, `make uninstall-plan`은 사용자 설정을 바꾸지 않고 대상을 출력한다. ZIP에도 각각의 설치·제거 명령이 포함된다.

## 설치용 빌드와 개발·배포용 빌드

`make install`은 `scripts/with-node.sh install`에서 Node 선택과 `npm ci`를 수행한 뒤 `scripts/install-source.mjs`를 실행한다. 앱을 임시 폴더에 빌드하고 ZIP 생성 없이 설치한다. 임시 빌드 폴더는 빌드 또는 설치의 성공·실패와 관계없이 정리한다. 정상 설치가 이미 있으면 소유 기록을 확인하고 `already_installed`로 유지하며 앱을 다시 빌드하지 않는다. 이 경우에도 앞 단계의 Node 준비와 `npm ci`는 수행될 수 있다.

설치 성공 또는 정상 기존 설치 확인 후에는 이 저장소의 `dist/WorkLog.app`, `dist/package/WorkLog/WorkLog.app` 두 경로만 중복 정리 후보로 확인한다. 설치 소유 기록의 앱과 전체 파일 목록·종류·내용·권한·심링크 대상이 일치하는 복사본만 제거한다. 수정·추가 파일, 앱 또는 상위 경로의 심링크, 다른 버전, 확인 실패가 있으면 해당 앱을 보존하고 결과의 `build_cleanup.preserved` 목록에 경로와 이유를 남긴다. 다른 앱을 검색하거나 `dist/package/WorkLog` 폴더 전체를 지우지 않는다. 예전 `dist/Work Log.app`도 정리 대상이 아니다. 설치가 실패하면 기존 빌드 산출물은 정리하지 않는다.

`make install INSTALL_ARGS='--source-app /path/to/WorkLog.app'`은 미리 빌드된 앱을 설치한다. 기존 Node만 사용하며 Node 다운로드·`npm ci`·앱 빌드를 건너뛴다. 명시한 원본 앱은 중복 정리 후보 경로에 있더라도 보존한다. ZIP의 설치 명령이나 `scripts/install.mjs`를 직접 실행하는 경우에도 원본 앱을 소비하거나 삭제하지 않는다.

`make build`는 개발·배포용 `dist/WorkLog.app`과 `dist/WorkLog-macos-arm64.zip`을 남긴다. ZIP에는 앱과 설치·제거 명령이 포함되며 포장용 임시 폴더는 정리한다. 설치용 빌드는 `dist`에 새 앱이나 ZIP을 만들지 않는다. 과거 ZIP, Node 캐시, 업무 데이터는 중복 앱 정리 대상이 아니다.

## 빌드용 Node 선택과 준비

`make build`와 `make install`은 `scripts/with-node.sh`로 Node를 선택한다. macOS Apple Silicon용 Node.js 22.17 이상이며 `node:sqlite`를 실행할 수 있어야 한다. 앱 안에 복사하므로 외부 Homebrew 동적 라이브러리 등에 의존하지 않는 실행 파일이어야 한다. Xcode의 Swift 컴파일러와 브라우저 검증용 Chrome은 별도 개발 환경 조건으로 유지한다.

명시한 `HARNESS_BUNDLE_NODE`가 가장 우선하고, 그다음은 `NODE`의 실행 파일 경로나 명령이다. 명시값이 실행되지 않거나 요구 조건을 충족하지 못하면 이유를 알리고 중단한다. 명시값이 없을 때는 현재 `PATH`의 `node`, `NVM_BIN`의 Node, `${NVM_DIR:-$HOME/.nvm}/versions/node/`의 설치본, 캐시 순서로 적합한 실행 파일을 찾는다. 셸에서 선택한 nvm 버전은 `PATH`로 재사용하며, 사용자 지정 nvm 디렉터리는 `NVM_DIR`로 찾는다. 예를 들어 `HARNESS_BUNDLE_NODE="$(nvm which current)" make install` 또는 `make install NODE="/custom/node/bin/node"`로 선택을 고정할 수 있다. 자동 탐색 중 발견한 부적합한 후보는 건너뛴다.

적합한 Node가 없으면 [공식 Node.js 22.23.2 배포본](https://nodejs.org/en/download/archive/v22.23.2)의 `node-v22.23.2-darwin-arm64.tar.gz`를 `https://nodejs.org/dist/v22.23.2/`에서 받아 공식 목록으로 확인해 스크립트에 고정한 SHA-256과 비교한다. 검증 후 프로젝트의 `.data/node/node-v22.23.2-darwin-arm64/`에 준비한다. `HARNESS_NODE_CACHE`는 캐시 루트를 바꾸며, `HARNESS_NODE_DOWNLOAD=0`은 다운로드를 금지한다. 다운로드를 끈 상태에서 적합한 실행 파일을 찾지 못하면 로컬 Node 지정 방법과 함께 실패한다. 사용할 수 없는 기존 캐시가 있으면 덮어쓰지 않고 다른 캐시나 Node 경로를 지정하도록 안내한다.

Node는 빌드하는 앱 안에 복사한다. 기존 시스템·nvm 설치본을 이동·수정하지 않으며, `sudo`, 전역 패키지 설치, `nvm install`, 셸 프로필 또는 영구 `PATH` 변경을 수행하지 않는다. 캐시는 개발 프로젝트의 빌드 입력이며 사용자 설치 소유 기록에 포함되지 않는다. `make uninstall`은 이 캐시나 재사용한 기존 Node를 제거하지 않는다.

`make install-plan`, `make uninstall-plan`, `make uninstall`, `make test`는 `--existing` 모드로 기존 Node만 사용하고 다운로드하지 않는다. 이 모드는 자동 탐색 시 nvm 다음으로 설치된 앱과 `dist/WorkLog.app`의 Node를 확인한 뒤 캐시를 찾으며, 버전과 `node:sqlite` 지원을 검사한다. `make test`에는 선택한 Node와 함께 사용할 npm도 필요하다. 제거 명령은 빌드가 필요 없으며 셸에 Node가 없어도 설치된 앱의 실행 파일을 후보로 사용할 수 있다. 필요한 Node를 찾지 못하면 사용자 설정을 바꾸지 않고 실패한다.

`npm run build:mac`을 직접 실행하는 경우에는 `HARNESS_BUNDLE_NODE` 또는 실행 중인 `process.execPath`를 사용한다. 번들 후보 검증은 기존 `dist/WorkLog.app`을 교체하기 전에 수행한다. Node 자동 준비와 의존성 설치까지 필요하면 `make build`를 사용한다. 설치용 임시 빌드와 중복 정리는 설치 갱신 정책을 바꾸지 않으므로, 정상 설치에 `make install`을 다시 실행하면 여전히 `already_installed`를 반환한다.

## Claude와 Codex 연결·해제

앱 설치 후 **연결 설정**에서 Claude와 Codex의 상태를 각각 확인하고 **연결** 또는 **연결 해제**를 선택한다. Claude 연결은 Claude 설정과 스킬 위치만, Codex 연결은 Codex 설정과 스킬 위치만 변경한다. Atlassian OAuth는 같은 연결 화면의 별도 설정이며 에이전트 연결 상태와 독립적이다.

| 엔진 | 연결할 때 추가하는 수집 훅 | 요청 스킬 연결 |
|---|---|---|
| Claude | `~/.claude/settings.json`의 WorkLog 훅 | `~/.claude/skills/work` |
| Codex | `~/.codex/hooks.json`의 WorkLog 훅 | `~/.agents/skills/work`, `~/.codex/worklog/skills/work` |

연결은 기존 설정을 백업하고 WorkLog 훅만 추가한다. 다른 사용자 훅이나 설정을 대체하지 않으며 스킬 위치에 다른 항목이 있으면 덮어쓰지 않는다. 연결 상태는 `connected`, `disconnected`, `needs_attention`으로 반환하며, 소유 기록과 현재 파일이 다르면 주의가 필요한 이유를 표시한다. 설치 완료 소유 기록을 확인할 수 없는 환경에서는 연결 변경을 허용하지 않는다.

연결 해제는 해당 엔진의 기록된 훅과 스킬 링크를 현재 내용과 비교해 제거한다. 다른 엔진의 연결, 사용자 설정, 업무 이력과 사용자 작업 유형은 유지한다. 앱과 서비스도 계속 사용할 수 있다. 이미 에이전트 세션에 로드된 지시문을 회수하거나 실행 중인 외부 세션을 종료했다고 주장하지 않는다. 앱 재실행·재설치가 해제한 연결을 다시 만들지 않는다.

GUI 관리 API는 `GET /api/agent-connections`로 두 엔진의 상태를 읽고, `POST /api/agent-connections/:engine`으로 연결하며, `DELETE /api/agent-connections/:engine`으로 해제한다. 변경 요청의 본문은 `{}`이며 `engine`은 `claude` 또는 `codex`다. 설치된 앱의 관리 서비스에서만 변경하며 임의 홈·파일 경로·실행 명령을 받지 않는다. 조회는 외부 에이전트 설정을 변경하지 않는다. 응답의 `available`은 연결 관리 가능 여부, `connections`는 엔진별 `engine`, `state`, `message`, `paths`를 제공한다.

## 단일 요청 스킬

앱의 실행 파일에 `skills/work/SKILL.md` 하나를 포함하고 GUI에서 연결한 엔진의 탐색 위치에만 심링크를 만든다. 스킬은 카탈로그의 책임 경계·입력 스키마를 읽고 사용자가 요청한 결과와 동작을 최대 24개 작업의 `prompt/steps` 계획으로 분할한다. 원문 인용·산출물 식별자·실제 자료 의존성을 붙여 `orchestrate`로 한 번 제출한다. 실행 서비스가 계획 검증·순서·동시성·`codex exec`/`claude -p` 실행·검증·수정·취소·재개를 소유한다. 업무별 스킬이나 스킬 안의 별도 실행기를 만들지 않는다. 단일 `run`의 자연어 분류는 제한된 호환 경로이며 복합 요청은 [구조화 계획](task-orchestration.md)을 사용한다.

연결된 스킬의 `scripts/harness`는 해당 설치의 Node·CLI·데이터 디렉터리에 고정된 실행 도우미다. 경로는 셸 인자로 인용하고 프롬프트는 JSON 파일로 전달한다. 내부 worker의 재귀 제출은 기존 CLI 경계로 차단한다. 앱 설치나 에이전트 연결이 유료 모델 사용이나 Jira 등의 외부 쓰기를 자동 승인하지 않는다.

두 엔진을 모두 연결하면 세 심링크가 설치 버전의 같은 스킬 디렉터리를 가리킨다. Codex의 공식 탐색 위치는 `.agents/skills`이며 `.codex/worklog`는 같은 설치 원본의 참조다. 기존 `CLAUDE.md`·`AGENTS.md`는 수정하지 않는다. 경로 선택은 [Codex 공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)와 [Claude 공식 스킬 문서](https://code.claude.com/docs/en/skills)를 따른다. 조직 정책이나 도구 환경이 스킬 로딩을 제한하면 자동 활성화를 가정하지 않는다.

## 소유 근거

`~/Library/Application Support/WorkLog/installation.json`에 형식 버전, 설치 UUID, 홈, 고정 실행 버전, LaunchAgent 정의·실행 인자, 배포 파일별 해시·권한을 기록한다. 새 설치는 형식 2이며 에이전트 훅·심링크 목록은 비어 있다. 이후 명시적 연결에서 엔진별 훅의 정확한 객체와 그룹 조건, 심링크 경로·대상·파일 식별자와 새로 만든 설정·디렉터리의 소유 근거를 같은 기록에 추가한다. 기존 형식 1의 소유 기록도 확인해 과거 자동 연결을 안전하게 해제·제거할 수 있다. 외부에 전달하거나 모델에게 출력시킬 데이터가 아니다.

WorkLog 수집 훅은 `HARNESS_WORKER=1`인 개별 작업에서는 Node 실행 전에 즉시 반환한다. 버전 조회·생성·검토·수정·요약 모두 같은 표식을 사용하고, 일반 에이전트 세션은 계속 수집한다. 다른 훅을 전체 비활성화하지 않는다. 이전 guard 없는 정확한 WorkLog 명령도 설치 소유 기록과 일치하면 제거할 수 있다.

훅 명령에는 `WORKLOG_INSTALL_ID`가 포함된다. 표준 훅 JSON에 도구가 알지 못하는 소유자 필드를 삽입하지 않는다. 연결 전 설정의 원본 백업은 `install-backups/<설치 UUID>/`에 보존하지만, 연결 해제나 제거 때 전체 백업으로 현재 설정을 덮어쓰지 않는다.

| 항목 | 제거 조건 | 보존 조건 |
|---|---|---|
| 개별 훅 | 연결할 때 기록한 명령·옵션·그룹 조건이 정확히 일치하는 항목이 하나 있음 | 명령/옵션 수정, 중복, 잘못된 JSON, 설정 심링크 교체 |
| 지시문 심링크 | 설치 위치·대상·기록된 파일 식별자가 일치 | 다른 대상, 일반 파일/디렉터리로 교체, 상위 디렉터리 심링크 |
| LaunchAgent | 소유 기록의 정의와 파일 해시 일치 | 변경된 정의 또는 다른 프로그램이 같은 서비스 이름을 사용 |
| 앱·고정 실행 파일 | 기록한 파일과 일치하고 추가된 사용자 파일 없음 | 수정·추가된 파일이 있으면 그 디렉터리 전체 보존 |
| 업무 데이터·자격증명 | 제거 대상 아님 | SQLite, 산출물, 로그, 백업, 사용자 작업 유형·실행 설정, Keychain 앱 자격증명과 토큰 유지 |

동일 그룹에 나중에 추가한 다른 훅은 보존한다. 기존 설정 파일과 `.claude`·`.codex`·`.agents` 폴더는 보존하며, 연결 과정에서 새로 만든 설정·빈 디렉터리도 소유 근거를 확인한 범위만 정리한다. 심링크 대상 디렉터리를 따라 재귀 삭제하지 않으며 설치 파일도 기록된 항목만 하나씩 확인해 제거한다. 수정된 훅이나 연결이 남으면 그것이 참조하는 실행 파일을 유지한다. GUI에서 추가한 연결 역시 `make uninstall`의 제거 대상이며 앱 설치 시점에 없었다는 이유로 남기지 않는다.

## 중단과 재실행

설치·제거·연결·연결 해제는 같은 로컬 잠금을 사용한다. 연결 소유 기록은 공유 설정 변경 전에 저장한다. 설치 도중 서비스 등록 등이 실패해도 기록으로 제거를 재개할 수 있다. 파일 복사가 일부만 끝난 경우 기록된 파일의 일치 여부를 확인하며 모르는 파일을 추정해 제거하지 않는다.

새 심링크는 생성 예정 상태와 실제 생성 후 파일 식별자를 구분한다. 생성 예정 기록만 남은 경로는 다른 프로그램이 만든 동일 대상 링크일 수도 있으므로 삭제 근거로 사용하지 않는다. 연결 상태는 링크뿐 아니라 설치된 Node·훅 파일·스킬 원본의 존재도 확인하며, 손상된 연결은 정상으로 표시하지 않는다.

동일한 정상 설치를 다시 설치하면 `already_installed`를 반환하고 외부 에이전트 설정을 읽거나 바꾸지 않는다. 기존 연결과 해제 상태는 유지한다. 기존 앱·서비스 설치의 변경·미완료 상태는 명확히 보고하고, 에이전트 연결 충돌은 GUI에서 해당 엔진의 상태로 확인한다. 이미 제거한 기록은 같은 이름의 새 파일에 대한 삭제 권한으로 재사용하지 않는다. 소유 기록 없는 과거 버전은 `unmanaged`로 남기며 이름 검색으로 정리하지 않는다.

활성화된 서비스는 설치한 Label·실행 인자가 일치할 때만 `launchctl bootout`한다. 서비스 제거가 비동기로 완료될 수 있으므로 최대 10초 동안 재조회하며 소유 관계와 종료를 확인한다. 서비스와 기록된 실행 프로세스의 종료를 확인하지 못하면 파일을 제거하지 않는다. 변경·누락된 기록으로 종료 권한을 추정하지 않는다.

CLI는 완료/이미 제거/미설치에 0, 보존된 충돌·미관리 설치에 2, 잘못된 인자·기록 등 실행 실패에 1을 반환한다. 설치·제거 후 기존 에이전트 세션이 이미 읽은 지시문까지 회수했다고 주장하지 않는다.

## 검증

`tests/e2e/source-install.test.mjs`는 실제 설치 코드를 임시 홈에서 실행해 외부 에이전트 설정 미변경, 임시 빌드 정리, 재설치 시 빌드 생략, 실패 시 원본 보존, 동일한 과거 앱 복사본 제거, 수정·추가 파일·심링크·명시적 원본 보존을 확인한다. 이전 설치용 빌드 변경에서는 설치·Node 준비·소스 설치 관련 E2E 72개를 통과했다. 별도로 네이티브 `make install`을 격리된 홈에서 실행해 설치 앱 하나와 번들 Node·서명을 확인했고, 배포용 ZIP의 내용·무결성 및 포장용 임시 폴더 정리를 검증했다. 이 과거 결과는 새 연결 분리 기능의 검증 완료를 뜻하지 않는다. 현재 사용자의 실제 앱·훅·LaunchAgent는 이 검증에서 변경하지 않았다.

`tests/e2e/node-bootstrap.test.mjs`는 Node가 없는 PATH에서 시작한 `make install`, 기존 Node·nvm·사용자 지정 경로·캐시 재사용, npm과 하위 프로세스의 PATH 전달, 구버전·다른 아키텍처·외부 라이브러리·SQLite 미지원, 체크섬 불일치·다운로드 실패·오프라인 실행을 격리된 환경에서 검증한다. 다운로드 도구는 대역을 사용하고 실제 버전·SQLite·라이브러리 검사 코드를 실행한다. 별도로 공식 22.23.2 배포본의 실제 다운로드·체크섬 검사·캐시 재사용과 기존 nvm Node를 사용한 `make build`, 번들 설치·서비스 시작·제거를 확인했다. 실제 사용자 설치는 변경하지 않았다.

`tests/e2e/install.test.mjs`는 임시 홈에서 실제 파일·설정·심링크와 CLI를 사용한다. 정상 제거, 재설치·재제거, 같은 그룹의 사용자 훅, 훅 편집·중복·손상, 링크 교체, 파일/상위 경로 심링크, 변경된 앱, 기록 누락·경로 변조, 설치 중단 복구, 같은 서비스 이름의 다른 프로그램, 데이터 보존을 검증한다.

`make install`/`make uninstall`의 CLI 연결을 검사하며 명시적으로 연결한 요청 스킬의 실행 도우미로 단일 자연어 요청 → 내부 업무 분류 → Codex 프로토콜 대역 → 산출물 전달과 실제 수집 훅 → work item을 검증한다. 연결 분리의 검증 대상은 설치·재설치의 외부 설정 미변경, 엔진별 연결·해제의 독립성, 충돌 보존, GUI에서 만든 연결을 포함한 제거다. 구조화 계획의 CLI·의존 실행·복구는 `tests/e2e/cli-orchestration.test.mjs`, `plans.test.mjs`, `plan-recovery.test.mjs`에서 별도로 확인한다. 이 검증이 실제 에이전트의 스킬 해석·분할 품질까지 입증하지는 않는다. 모델 대역을 사용하므로 유료 호출은 없다. 사용자 홈의 실제 훅·LaunchAgent·Keychain은 변경하지 않는다. 서비스 등록·종료 시나리오는 launchctl 대역으로 소유 검사를 검증하며 실제 로그인 재시작 시험과 구분한다.

## 앱 종료와 다시 열기

메뉴 막대의 `WorkLog 종료`는 제거 명령이 아니다. 설치 파일·훅·스킬·업무 데이터를 유지하고 관리 서비스를 중지한다. 실행 서비스에는 내부 관리 작업만 취소하도록 요청한다. 사용자 요청으로 실행 중이거나 대기 중인 본 작업과 DAG의 후속 작업은 유지하며, 모두 끝난 뒤 실행 서비스도 정상 종료한다. 외부 Codex·Claude 세션은 종료 대상이 아니다. 앱이 닫힌 동안 훅 이벤트는 기존 로컬 스풀에 남고, 다음 실행에서 수집한다.

`runtime`의 LaunchAgent는 비정상 종료 시 재시작하되 정상 종료 시에는 재시작하지 않는다. 앱을 다시 열면 소유가 확인된 서비스만 등록·시작하고, 아직 진행 중인 실행 서비스에는 종료 대기 해제를 요청한다. 시작·종료는 설치/제거와 같은 잠금으로 직렬화한다. 종료 실패 시 앱을 유지해 오류를 보여 주며 종료됐다고 표시하지 않는다. 개발용 번들은 실제 사용자 설치의 서비스를 제어하지 않는다.

`tests/e2e/install.test.mjs`는 지연된 launchd 제거, 종료 시간 초과 후 안전한 재시도, 사용자 작업이 있는 종료와 재연결, 정상 종료 후 휴면 서비스 시작을 추가로 검증한다. `make uninstall`은 명시적인 설치 제거이므로 앱 종료와 달리 모든 설치 소유 서비스를 종료한 뒤 파일을 제거한다.


## 사용자 정의와 메뉴 아이콘

사용자 작업 유형과 지시문·모델 설정은 앱 밖의 `DATA_ROOT/execution-settings.json`에 보관한다. 이 파일은 설치 소유 항목에 포함하지 않으므로 제거·재설치 후 유지한다. 기존 실행의 정의와 산출물도 별도로 보존한다. `tests/e2e/install.test.mjs`는 임시 홈에서 실제 패키지 런타임으로 등록·편집 후 제거·재설치하고 설정 원문, 카탈로그, 실행 결과가 유지되는지 확인한다.

GUI의 탐색·설정·캘린더 이동·빠른 패널 아이콘은 정적 inline SVG이며 CSS를 앱과 함께 배포한다. 글꼴 문자, 외부 CDN, JavaScript 초기화에 의존하지 않는다. 메뉴 막대는 번들 PNG를 사용하며 리소스를 읽지 못하면 AppKit 벡터로 대체한다. 지원 범위인 macOS 13 이상 Apple Silicon 앱에서 사용할 리소스이며, 설치 대상 OS·아키텍처를 확대하는 변경은 아니다. GUI 테스트는 외부 요청을 차단하고 글꼴을 바꾼 상태의 1×/2× 배율 및 스크립트 비활성 상태를 확인한다.
