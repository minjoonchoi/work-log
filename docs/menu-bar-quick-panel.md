# macOS 메뉴 막대 빠른 패널

최초 작성 2026-09-18 · 알림 구조 갱신 2026-09-19. 메뉴 막대에서 현재 업무를 확인하고 전체 창의 원하는 화면으로 이동하는 기능이다. 작업 실행과 이력 수집은 기존 서비스가 계속 소유한다.

## 동작

- 메뉴 막대 아이콘을 클릭하면 380pt × 최대 600pt 팝오버를 열고, 다시 클릭하거나 바깥을 누르면 닫는다. 아이콘 옆 숫자는 현재 work item 수다.
- 알림·현재 작업·최근 업무를 각각 최대 3·5·5개 표시한다. 초과분은 더보기로 해당 목록을 연다. 목록만 스크롤하며 업무 목록·오늘 캘린더·연결 설정은 하단에 고정한다.
- 업무를 누르면 해당 업무 상세를, 알림을 누르면 전체 창의 정확한 알림을 연다. 알림에는 소속 업무·문제·원인·발생 시각·조치 이름을 표시한다. 전체 화면의 기존 검색·상세 선택을 지우고 새 목적지로 이동한다. 웹 화면 준비 완료 메시지 이후에 목적지를 전달하므로 최초 열기에서도 선택한 대상을 보존한다.
- 로그인 자동 시작용 LaunchAgent는 `--background`를 사용해 창을 띄우지 않는다. 직접 실행하거나 Finder에서 다시 열면 업무 목록의 메인 창을 연다. 메뉴 막대 아이콘은 빠른 패널을 열며 우클릭 메뉴는 화면 바로가기와 WorkLog 종료를 제공한다. 전체 창만 닫으면 서비스와 기록 수집을 유지한다.
- 설치된 앱을 시작하면 번들의 서비스 제어 도우미가 설치 소유 기록을 확인해 실행·관리 서비스를 연결한다. WorkLog 종료는 내부 요약·메타데이터 작업을 정리하고 서비스 종료 결과를 확인한 뒤 앱을 닫는다. 사용자 요청 작업이 남아 있으면 해당 작업을 계속 수행할 서비스를 보존한다. 사용자가 직접 연 Claude/Codex 에이전트 세션에는 종료 신호를 보내지 않는다.
- 서비스 시작 중 종료를 요청하면 시작 처리가 끝난 뒤 종료한다. 종료 실패나 확인할 수 없는 결과는 앱을 유지하며 오류를 알린다. 다시 앱을 실행하면 서비스를 시작하거나 진행 중인 서비스에 재연결한다. 개발·미리보기 앱은 설치된 앱과 데이터 경로가 다르므로 설치 서비스의 시작·종료를 수행하지 않는다.

## 표시 근거

`GET /api/quick`은 기존 인증을 적용하며 업무의 제목·ID·최근 활동 시각·표시 상태와 그룹별 수를 반환한다. 알림은 `id`, `revision`, 소속 업무, `kind`, `title`, `message`, `occurred_at`, 대상 참조와 `action_label`을 포함한다. 원본 입출력, 산출물 본문, 내부 worker 로그는 가져오지 않는다. 업무를 열 때 기존 상세 API를 사용한다. 알림 선택은 `{ "view": "notifications", "notification_id": "…" }`로 전달한다.

| 그룹 | 근거 |
|---|---|
| 알림 | 현재 남아 있는 실행·제목/설명·세션 요약 실패, Jira 이슈 생성·상태/내용 반영·업무 로그 동기화 실패 또는 전송 결과 미확인. 원인별 알림으로 집계하며 발생 시각이 최신인 항목부터 표시 |
| 현재 작업 | 비내부 run의 running은 **작업 실행 중**, pending은 **실행 대기**. 실행 중/대기 run이 없고 사용자 세션의 미응답 입력이 있으면 **작업 중** |
| 최근 업무 | 현재 작업에 포함되지 않은 업무를 최근 활동순으로 표시. 알림 유무만으로 업무 전체를 차단하거나 완료라고 판정하지 않음 |

여러 에이전트 세션을 병합한 업무는 현재 작업·최근 업무에서 하나로 집계한다. 알림은 업무 수가 아니라 해결하거나 확인할 문제 수이므로 한 업무에 여러 알림이 있을 수 있다. 알림 수를 현재·최근 업무 수에 더해 전체 업무 수로 해석하지 않는다. 제목·설명 생성 같은 내부 run의 진행은 현재 작업 수에 포함하지 않는다. **작업 중**는 수집한 입력에 아직 대응하는 종료 기록이 없다는 뜻으로 외부 에이전트의 실제 프로세스 생존을 보장하지 않는다. 20분 세션 구분 규칙과 원본 시각은 그대로 유지한다.

내부 작성 실패는 모든 과거 worker run을 모으지 않고 `writing_requests`의 대상별 최신 요청과 현재 `session_summaries` 상태에서 확인한다. 새 재작성 요청이 접수되거나 성공하면 이전 실패는 알림에서 해소되고 실패 이력은 남는다. 제목·설명을 직접 편집하거나 병합으로 이전 메타데이터 대상이 바뀌어도 그 버전의 실패는 해소된다. 세션 요약 실패는 현재 대표 업무를 따라가며 제목 편집만으로 해소되지 않는다. 입력 크기 제한으로 worker를 시작하지 못한 요약 실패도 표시한다. 요약·메타데이터 실패가 사용자 본 작업 전체의 실패를 뜻하지는 않는다.

### 알림 해소와 기록 보존

**알림 지우기**는 그 알림의 현재 버전만 숨긴다. 원본 입출력·실패 기록·Jira 상태·산출물을 지우거나 성공으로 바꾸지 않으며, 진행 중인 작업을 취소하지 않는다. 새 시도가 다시 실패하거나 새로운 문제가 생기면 새 알림을 표시한다. 진행 중·재시도 중·해결된 문제는 알림 목록에서 제외한다. 오래된 알림에서 조치를 선택한 경우에는 최신 대상 상태를 다시 확인한다.

실행 문제는 연결된 작업, 작성 문제는 해당 제목·설명 또는 세션 요약, Jira 문제는 해당 이슈나 업무 로그로 이동해 확인한다. 전송 결과가 불명확한 Jira 요청은 결과 확인을 우선하고 자동으로 같은 쓰기를 반복하지 않는다. 삭제된 업무의 알림은 업무를 복원하기 전까지 표시하지 않는다.

GUI는 업무 이력과 실행·동기화 문제를 관리하며, 에이전트 프롬프트 입력이나 사용자 질문 감지·답변 기능은 제공하지 않는다. 이전 `사용자 답변 필요`·`확인 필요` 화면의 바로가기는 알림으로 연결한다. 기존 도구 이벤트를 사용자 질문 알림으로 재해석하지 않는다.

보이는 패널은 SSE 변경 알림과 4초 폴링으로 갱신한다. 숨긴 패널의 구독·조회는 중단하고 다시 열 때 최신 상태를 조회한다. 네이티브 메뉴 막대의 수는 패널과 별도로 4초마다 확인한다. 관리 연결이 끊기면 마지막 화면과 확인 시각을 남겨 오래된 정보임을 표시한다. 관리가 연결되어도 실행 서비스가 끊겼으면 running 항목을 `실행 상태 미확인`으로 표시한다.

최초 페이지 요청이 실패하면 페이지 안의 재연결 코드도 실행되지 않는다. 네이티브 앱은 메인 창과 빠른 패널의 로딩 실패·WebKit 종료를 각각 기록하고 관리 서비스가 응답한 뒤 실패한 화면만 다시 연다. 포트와 토큰이 그대로여도 복구하며 정상 화면의 편집 내용은 유지한다. 설치된 앱 경로는 `~/Applications/WorkLog.app`, 데이터 경로는 `~/Library/Application Support/WorkLog/`이다.

## 검증과 이전 구현 기록

아래 대기 주체·질문 감지 검증은 알림 통합 전 구현의 기록이다. 현재 제품의 질문 감지 지원을 뜻하지 않는다. 2026-09-19 알림 통합과 자동 작성 변경 후 서비스 E2E 365개·GUI E2E 67개가 통과했다. 원본 기록을 보존하는 알림 지우기, 재시작·새 실패, 정확한 대상 이동, 질문 도구 이벤트의 무알림 처리, 비활성 세션의 Jira 경고 이동을 포함한다. 근거는 `output/worklog-final-verification.json`이다.

2026-09-19: `tests/e2e/native-connection.test.mjs`에서 실제 Swift/AppKit/WKWebView를 사용해 초기 연결 실패 후 동일 포트 회복, WebKit 종료 알림, 로그인 숨김 시작, 일반 실행·재열기를 검증한다. 별도 시나리오는 실제 관리 서비스와 정적 페이지·모듈 JavaScript·인증 주입·업무 표시를 확인한다. 아래 숫자는 이전 변경 당시의 기록이다.

`tests/e2e/native-lifecycle.test.mjs`는 실제 AppKit 종료 요청과 비동기 subprocess를 사용한다. 임시 도우미로 시작·종료 순서, 사용자 작업 유지 결과, 종료 실패 후 창·알림 보존과 재시도, 시작 실패, 잘못된 응답 및 개발 앱의 서비스 제어 생략을 검증한다. 이 테스트는 실제 사용자 LaunchAgent나 서비스에 접근하지 않는다.

최초 빠른 패널의 서비스 103개·GUI 37개 검증은 `output/self-verification/2026-09-18T04-40-11.784Z/verification.md`에 보관한다. 대기 주체 구분 변경 후 전체 등록 검사 `harness.e2e`를 하네스의 `checks.run` → `verification.report`로 실행해 서비스 110개·GUI 40개 모두 통과했다. 해당 검사 전후 소스 지문이 일치하며 결과는 `output/self-verification/2026-09-18T05-40-20.546Z/verification.md`에 보관한다.

필터에 맞는 빈 목록 안내를 보완한 후 GUI 검사에서 캘린더 더보기의 키보드 포커스 유실 1건이 발견됐다(`output/self-verification/2026-09-18T05-44-18.915Z/verification.md`: 39/40 통과). 동일한 캘린더 스냅샷으로 DOM을 다시 생성하지 않도록 수정했고, 중복 갱신 후 포커스를 확인하는 재현 시나리오를 추가해 3회 연속 통과했다.

최종 GUI 전체 재검사는 40/40 통과했다(`output/self-verification/2026-09-18T05-47-24.393Z/verification.md`, 재시도·건너뜀 없음). 최종 앱 빌드·ad-hoc 서명도 완료했다. 사용자 설치본은 교체하지 않았다.
