# macOS 메뉴 막대 빠른 패널

2026-09-18. 메뉴 막대에서 현재 업무를 확인하고 전체 창의 원하는 화면으로 이동하는 기능이다. 작업 실행과 이력 수집은 기존 서비스가 계속 소유한다.

## 동작

- 메뉴 막대 아이콘을 클릭하면 380pt × 최대 600pt 팝오버를 열고, 다시 클릭하거나 바깥을 누르면 닫는다. 아이콘 옆 숫자는 현재 work item 수다.
- 사용자 답변 필요·현재 작업·확인 필요·최근 업무를 각각 최대 3·5·3·5개 표시한다. 초과분은 더보기로 해당 목록을 연다. 목록만 스크롤하며 업무 목록·오늘 캘린더·연결 설정은 하단에 고정한다. 사용자 질문이 없으면 질문 영역을 생략한다.
- 업무를 누르면 해당 업무 상세를 전체 창에서 연다. 전체 화면의 기존 검색·상세 선택을 지우고 새 목적지로 이동한다. 웹 화면 준비 완료 메시지 이후에 목적지를 전달하므로 최초 열기에서도 선택한 업무를 보존한다.
- 로그인 자동 시작용 LaunchAgent는 `--background`를 사용한다. 직접 실행하면 빠른 패널을 연다. 우클릭 메뉴는 화면 바로가기와 GUI 종료를 제공한다. 전체 창을 닫거나 GUI를 종료해도 별도 서비스의 작업과 기록은 유지된다.

## 표시 근거

`GET /api/quick`은 기존 인증을 적용하며 제목·ID·최근 활동 시각·표시 상태와 정확한 그룹별 수를 반환한다. 원본 입출력, 산출물 본문, 내부 worker 로그는 가져오지 않는다. 업무를 열 때 기존 상세 API를 사용한다.

| 그룹 | 근거 |
|---|---|
| 사용자 답변 필요 | 대응하는 도구 종료 기록이 없는 명시적 질문 도구 요청이 있음. 현재 지원하는 근거는 사용자 Claude 세션의 `AskUserQuestion` PreToolUse와 일치하는 turn/call ID |
| 현재 작업 | 비내부 run의 running은 **작업 실행 중**, pending은 **실행 대기**. 실행 중/대기 run이 없고 사용자 세션의 미응답 입력이 있으면 **에이전트 응답 대기** |
| 확인 필요 | 위 조건이 없으며 실패·차단·중단된 비내부 run이 있음. 일반적인 blocked를 사용자 답변 필요로 해석하지 않음 |
| 최근 업무 | 위 조건에 포함되지 않은 업무. 요청 종료 여부를 임의로 완료라고 판정하지 않음 |

여러 에이전트 세션을 병합한 업무도 하나로 집계한다. 사용자 질문이 있으면 해당 영역에 우선 배치하고 다른 에이전트의 실행 상태는 추가 상태로 함께 표시한다. 이후 우선순위는 작업 실행 중 → 실행 대기 → 에이전트 응답 대기 → 확인 필요 → 최근 업무다. 타이틀·설명 생성 같은 내부 run은 현재 작업 수에 포함하지 않는다. **에이전트 응답 대기**는 수집한 입력에 아직 대응하는 종료 기록이 없다는 뜻으로 외부 에이전트의 실제 프로세스 생존을 보장하지 않는다. 20분 세션 구분 규칙과 원본 시각은 그대로 유지한다.

### 사용자 질문의 근거와 종료

`UserPromptSubmit`과 `Stop`만으로는 사용자 답변이 필요한 질문인지 알 수 없다. 대화 본문의 물음표나 일반 blocked 메시지로 추정하지 않는다. 현재는 [Claude 공식 훅의 AskUserQuestion 입력](https://code.claude.com/docs/en/hooks#pretooluse-input)에 명시된 질문 목록을 기존 도구 이력에서 읽는다. 원본 입출력에 질문 도구의 내용을 가짜 assistant 응답으로 추가하지 않는다. 질문 내용은 업무 상세의 별도 영역에서 표시하며 답변은 원래 Claude 에이전트 세션에서 한다.

질문 시작과 종료는 같은 에이전트 세션·call ID로 연결한다. 대응하는 PostToolUse/PostToolUseFailure 또는 해당 turn의 출력·실패·중단, 세션 종료가 수집되면 질문 대기를 종료한다. 새 입력은 이전 질문을 대체한다. 도구 실패나 새 입력 때문에 질문 표시가 사라졌다고 답변이 있었다는 기록을 만들지 않는다. 수집된 원본은 보존하며 재전송·늦은 수집은 원본 시각과 이벤트 키로 재투영한다. `user_questions`는 이력에서 다시 만들 수 있는 파생 테이블이고 초기 업그레이드 시 기존 이벤트도 재투영한다.

**지원 제한:** 현재 Codex 질문 이벤트와 헤드리스 worker의 구조화된 사용자 질문 계약은 연결하지 않았다. Codex의 미응답 입력은 에이전트 응답 대기로, 근거가 없는 blocked는 확인 필요로 남긴다. 사용자 질문 감지의 전체 엔진 지원을 보장하지 않는다. 이번 변경은 질문의 관찰·표시이며 GUI에서 네이티브 에이전트에 답변을 대신 제출하는 기능은 포함하지 않는다.

보이는 패널은 SSE 변경 알림과 4초 폴링으로 갱신한다. 숨긴 패널의 구독·조회는 중단하고 다시 열 때 최신 상태를 조회한다. 네이티브 메뉴 막대의 수는 패널과 별도로 4초마다 확인한다. 관리 연결이 끊기면 마지막 화면과 확인 시각을 남겨 오래된 정보임을 표시한다. 관리가 연결되어도 실행 서비스가 끊겼으면 running 항목을 `실행 상태 미확인`으로 표시한다.

## 검증

최초 빠른 패널의 서비스 103개·GUI 37개 검증은 `output/self-verification/2026-09-18T04-40-11.784Z/verification.md`에 보관한다. 대기 주체 구분 변경 후 전체 등록 검사 `harness.e2e`를 하네스의 `checks.run` → `verification.report`로 실행해 서비스 110개·GUI 40개 모두 통과했다. 해당 검사 전후 소스 지문이 일치하며 결과는 `output/self-verification/2026-09-18T05-40-20.546Z/verification.md`에 보관한다.

필터에 맞는 빈 목록 안내를 보완한 후 GUI 검사에서 캘린더 더보기의 키보드 포커스 유실 1건이 발견됐다(`output/self-verification/2026-09-18T05-44-18.915Z/verification.md`: 39/40 통과). 동일한 캘린더 스냅샷으로 DOM을 다시 생성하지 않도록 수정했고, 중복 갱신 후 포커스를 확인하는 재현 시나리오를 추가해 3회 연속 통과했다.

최종 GUI 전체 재검사는 40/40 통과했다(`output/self-verification/2026-09-18T05-47-24.393Z/verification.md`, 재시도·건너뜀 없음). 최종 앱 빌드·ad-hoc 서명도 완료했다. 사용자 설치본은 교체하지 않았다.

- `tests/e2e/quick-panel.test.mjs`: 실제 훅 subprocess의 입력/Stop, 목록 상한·정확한 수, 내부 worker 제외, 병합·중단·재시작, run 상태 전이, 인증.
- `tests/ui/quick-panel.spec.mjs`: 작은 화면의 스크롤·더보기, 정확한 목적지, 실시간 갱신·연결 복구, 숨긴 화면의 조회 중단, 기존 검색 초기화·오늘 캘린더, 긴 제목·HTML 문자 표시.
- `tests/e2e/waiting-states.test.mjs`: 실제 훅 subprocess의 질문·도구 답변·실패, 일반 blocked 구분, 늦은 종료·새 입력·세션 종료, 병합과 동시 진행, 기존 DB 재투영, 실제 dispatcher 동시성 제한과 실행 대기 해제.
- `tests/ui/waiting-states.spec.mjs`: 대기 주체별 표시·필터·실시간 전환, 질문 상세와 원본 입출력 분리, 질문 문자열 이스케이프·동시 진행 보존.
- 설치 E2E는 격리된 임시 홈에서 GUI LaunchAgent의 `--background` 인자를 확인한다.
- 별도 데이터 디렉터리·bundle ID를 사용하는 Preview 앱에서 실제 AppKit 팝오버, 항목 선택 → 업무 상세, 창 닫은 후 빠른 패널 접근, 응답 수집 후 현재 수 2→1 및 최근 목록 이동을 확인했다. 유료 모델 호출과 사용자 데이터 변경은 없다.
- macOS 앱 컴파일·ad-hoc 서명, 번들 Node/서비스/훅 실행, ZIP 무결성 검사가 통과했다. 실제 사용자 LaunchAgent 설치나 로그인 재부팅 시험은 수행하지 않았다.

대기 주체 구분은 격리한 Preview 앱에서도 사용자 답변 필터·질문 상세·PostToolUse 이후 에이전트 응답 대기로 전환하는 것을 확인했다. 기록은 `output/waiting-native/verification.json`에 보관한다.
