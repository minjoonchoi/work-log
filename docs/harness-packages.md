# WorkLog 자동 생성과 선택형 하네스

WorkLog의 이력 관리와 에이전트 작업 위임은 독립 기능이다. 이력 수집만 연결해도 업무·세션 탐색, 자동 제목·설명, 세션 요약을 사용할 수 있다. 하네스 위임을 해제하거나 직무 패키지를 제거해도 이 기능과 이미 수집한 데이터는 유지한다.

## 연결 설정

Claude와 Codex 카드마다 두 연결을 관리한다.

| 연결 | 추가하는 항목 | 해제 효과 |
|---|---|---|
| 이력 수집 | 해당 엔진의 WorkLog 시스템 훅 | 이후 수집 연결 제거. 기존 이력·요약 보존 |
| 하네스 위임 | `work` 요청 스킬 심링크 | 해당 엔진의 새 하네스 위임 중지. 수집 훅 보존 |

다른 프로그램의 훅·스킬은 변경하지 않는다. 두 연결은 각각의 소유 기록과 실제 파일을 비교해 상태를 표시한다. 하네스 위임 연결이 정상이어도 직무 패키지를 설치해야 그 작업을 요청할 수 있다. 원본 세션과 같은 업무에 연결하는 위임은 해당 세션의 수집된 입력도 필요하다.

이미 접수된 실행과 계획의 후속 작업은 접수 당시의 정의로 계속 진행한다. 연결 해제가 이미 에이전트 문맥에 읽힌 스킬을 회수하지는 않지만, 설치 환경의 새 에이전트 위임은 서비스에서 연결 상태를 다시 확인한다. 기존 실행의 취소는 별도 실행 취소 기능을 사용한다.

## 직무별 작업 설치

연결 설정의 직무 목록에서 필요한 묶음만 설치한다. 설치·제거는 앱에 포함된 검증된 작업 정의의 사용 여부를 변경하는 로컬 설정이다. 모델이나 추가 스킬을 다운로드하지 않으며 직무별 스킬을 복제하지 않는다.

| 패키지 | 담당 유형 |
|---|---|
| PO | 제품 문제·조사·PRD·요구사항·백로그·지표 |
| PM | 프로젝트·범위·WBS·일정·위험·진행·공유와 인수인계 |
| 프런트엔드 | HTML 목업·FE 계획과 구현·컴포넌트·UI·접근성·FE 테스트 |
| 백엔드 | 엔티티·API·BE 계획과 구현·마이그레이션·BE 테스트·쿼리 |
| 공통 | 설계·다이어그램·일반 문서와 텍스트·조사·공통 개발과 검토·검사 실행 |

여러 직무와 공통 패키지를 함께 설치할 수 있다. 패키지 선택은 같은 로컬 WorkLog를 사용하는 Claude·Codex에 공통 적용하며, 엔진별 위임 연결 여부는 별도로 유지한다. 공개 작업 하나는 한 패키지에 속하며, 직무 설치가 같은 작업 정의를 복제하지 않는다. 공통 작업이 필요하면 공통 패키지도 선택한다. 설치되지 않은 작업은 요청 카탈로그와 새 계획에서 사용할 수 없고 명시적인 task ID나 자연어 요청도 같은 정책을 따른다.

신규 설치는 직무 패키지가 없는 상태에서 시작한다. 이전 버전에서 사용하던 데이터에 패키지 설정이 없다면 기존 전체 카탈로그를 유지하며, 이후 사용자가 선택한 설치 상태를 저장한다. 앱 업데이트가 기존 선택을 바꾸지 않는다.

## 자동 생성 작업 설정

작업 실행 설정은 **WorkLog 자동 생성**과 **하네스 작업**으로 나뉜다. WorkLog 자동 생성에는 앱이 사용하는 다섯 유형이 있다.

| 유형 | 용도 |
|---|---|
| `session.summarize` | 세션 요약 |
| `text.rewrite` | 업무 제목·설명과 세션 요약 재작성, 자동 메타데이터 갱신 |
| `work.report.create` | 선택 기간의 업무 요약 |
| `work-item.result.summarize` | Jira 완료 결과 요약 댓글 본문 |
| `task.type.draft` | 사용자 작업 유형 등록 전 초안 |

이 그룹에는 자동 예약과 GUI 버튼으로 요청하는 생성 작업이 모두 포함된다. 각 지시문·backend·model·effort는 기존과 같이 개별 설정하며, 자동 생성 기준 횟수는 자동 작성 설정에서 관리한다. 패키지 설치 여부가 이 다섯 작업을 비활성화하지 않는다. 사용자 요청을 처리하는 일반 `text.generate`는 공통 하네스 작업이다.

사용자 등록 유형은 템플릿의 패키지를 따른다. 제거해도 등록 내용과 지시문·모델 설정은 남고, 다시 설치하면 같은 유형을 사용할 수 있다. 새 유형과 초안의 템플릿 후보는 설치된 유형만 제공한다. 사용자 유형 삭제는 별도 명시적 삭제 동작이다.

## 저장과 API

`DATA_ROOT/harness-packages.json`에 형식 버전·revision·설치된 패키지 ID를 보관한다. `execution-settings.json`에는 기존 사용자 유형과 실행 설정을 유지한다. 두 파일과 업무 이력은 `make uninstall` 후에도 보존하며 재설치 시 재사용한다.

- `GET /api/agent-connections`: 엔진별 `tracking`, `harness` 연결 상태와 실제 훅 수집 상태 조회.
- `POST|DELETE /api/agent-connections/:engine/tracking`: 이력 수집 연결·해제. 본문 `{}`.
- `POST|DELETE /api/agent-connections/:engine/harness`: 하네스 위임 연결·해제. 본문 `{}`.
- `GET /api/harness-packages`: 패키지별 설치 여부·유형 목록·revision 조회.
- `PUT /api/harness-packages/:id`: `{ "installed": true, "revision": 0 }` 형태로 변경. 오래된 revision은 충돌로 거부.

이전 엔진 단위 연결 API는 두 연결을 함께 변경하는 호환 경로로 남긴다. GUI는 분리된 API를 사용한다. 모든 API는 기존 로컬 서비스 인증을 적용한다. 패키지 변경은 외부 에이전트 설정이나 Jira 데이터를 수정하지 않는다.
