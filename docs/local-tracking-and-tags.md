# 로컬 업무 추적과 유형 태그

WorkLog의 기준 데이터는 로컬 SQLite의 work item, 에이전트 세션, 입출력 이벤트와 Work Item Session이다. Jira 연결은 선택 사항이다. OAuth 설정·인증이나 Jira 응답이 없어도 기록 수집, 목록·캘린더·이력 탐색, 실행·산출물 관리, 요약·제목 작성, 태그 편집, 병합·삭제·복원을 사용할 수 있다. 모델 생성 작업의 Claude/Codex 인증과 연결은 기존 실행 정책을 따른다.

## Jira에 나중에 연결하기

| 로컬 기준 | Jira 기록 | 동작 |
|---|---|---|
| Work item | 새 이슈 또는 선택한 기존 이슈 | 새 이슈에 현재 제목·설명을 사용한다. 기존 이슈 내용 변경은 명시적 반영으로 처리한다. |
| 종료된 Work Item Session | 업무 로그 한 개 | 유효한 요약, 시작 시각, 입출력 관측 구간의 초를 전송한다. |
| 같은 세션의 재요약 | 같은 업무 로그 수정 | 기존 worklog ID를 유지하고 댓글·시각·시간을 갱신한다. |

나중에 이슈를 만들거나 연결하면 이미 종료되고 요약된 세션도 전송 대상이 된다. 진행 중인 세션, 미완료·오래된 요약, 양수 관측 시간을 확인할 수 없는 구간은 완료된 업무 로그로 보내지 않는다. 연결이 끊겨도 로컬 기록과 작성은 계속되며 재연결 후 미전송 기록을 처리한다. GUI에서 연결을 해제하면 OAuth 토큰만 제거하며 업무 기록과 Keychain의 앱 자격증명은 유지한다.

`jira_worklogs.session_id`가 기본 키다. 세션당 operation ID와 원격 worklog ID를 유지하며 재시도·중복 이벤트·재시작으로 새 로그를 추가하지 않는다. 응답 유실은 원격 기록을 대조하고 결과가 불명확하면 자동 재생성을 보류한다. 세션 상세에는 업무 로그의 실제 Jira 이슈 대상을 표시한다.

병합된 세션의 원래 Jira 연결과 이미 전송한 로그는 보존한다. 여러 이슈가 연결된 병합 업무에서는 원래 업무의 연결 또는 대표 업무의 연결을 사용하고, 대상이 하나로 정해지지 않는 세션은 임의 전송하지 않는다. 기존 로그를 다른 이슈로 이동·복제하거나 원격 이슈를 자동 병합하지 않는다. 자세한 전송·복구 규칙은 [Jira 업무 로그](atlassian-worklogs.md)에 있다.

## 업무 유형 태그

한 work item에 여러 태그를 붙일 수 있다. 기본 제안은 `기획`, `설계`, `개발`, `검토`, `테스트`, `조사`, `문서`, `운영`이며 직접 입력한 태그도 사용한다. 태그가 없으면 **미분류**로 표시한다. 태그는 업무를 찾고 집계하는 분류이며 실행기의 작업 유형·권한·워크플로나 Jira의 이슈 유형을 바꾸지 않는다.

- 상세의 **업무 유형 → 태그 편집**에서 추가·제거한다. 목록과 세션별 목록에 같은 업무 태그를 표시한다.
- **업무 유형 필터**는 검색·Jira 연결 필터와 함께 적용된다. 세션별 목록도 소속 업무의 태그로 좁힌다.
- 제목·설명·요약 재생성은 태그를 바꾸지 않는다. 태그 편집도 제목·설명의 수동 편집 보호를 켜거나 최근 활동 시각을 바꾸지 않는다.
- 병합은 중복 없는 태그 합집합을 대표 업무에 보관한다. 허용 개수를 넘으면 원본을 유지하고 병합을 거절한다.
- 휴지통 이동은 태그를 보존한다. 기본 태그별 건수에는 숨긴 업무를 제외하며 복원하면 다시 포함한다.
- 동시 편집·병합으로 버전이 바뀌면 저장을 거절하고 사용자가 최신 태그를 불러온 뒤 다시 편집한다.
- 태그는 로컬 분류다. 태그 편집만으로 Jira labels나 이슈를 변경하지 않는다.

## 저장·조회 계약

`work_item_tags(work_item_id, tag)`는 두 열을 기본 키로 사용하고 태그별 조회 인덱스를 둔다. 문자열은 NFKC 정규화, 앞뒤·연속 공백 정리, 영문 소문자화를 거친 값으로 식별한다. 제어 문자는 거절한다. 태그당 1~40자, 업무당 최대 20개이며 같은 태그를 반복 입력해도 하나만 저장한다. 자동 AI 분류나 전역 이름 변경은 제공하지 않는다.

| 로컬 관리 API | 용도 |
|---|---|
| `GET /api/items`, `GET /api/items/:id` | 각 업무의 `tags: string[]` 반환 |
| `PUT /api/items/:id/tags` | `{ "version": 3, "tags": ["설계", "개발"] }`를 버전 검사 후 저장 |
| `GET /api/tags` | 보이는 대표 업무의 태그별 `{name,count}` 목록 |
| `GET /api/tags?trash=true` | 휴지통 업무의 태그별 건수 |
| `GET /api/items?tag=개발` | 정규화한 태그와 일치하는 업무 |
| `GET /api/items?untagged=true` | 태그 없는 업무. `tag`와 동시 사용 불가 |

향후 대시보드는 대표 work item과 세션 ID를 기준으로 중복을 제거해 집계한다. 한 업무가 여러 태그에 속하므로 유형별 건수를 단순 합산한 값은 전체 고유 업무 수가 아니다. 세션 시간도 입출력 관측 구간이며 사람의 실투입 시간으로 표시하지 않는다. 이번 구현은 분류·필터·집계 원본까지이며 대시보드 화면을 추가하지 않는다.

## 시나리오 검증

`tests/e2e/local-jira-tracking.test.mjs`는 Jira 설정·OAuth·Keychain 도구가 없는 상태의 로컬 작업, 나중 연결에 따른 과거 세션 전송, 같은 로그의 갱신·실패 재시도·응답 유실 복구, 연결 해제 후 로컬 작업, 병합된 세션의 원래 이슈 유지를 검증한다. `tests/e2e/item-tags.test.mjs`와 `tests/ui/item-tags.spec.mjs`는 태그 편집·검색·필터·정규화·충돌·재시작·병합·휴지통 복원과 원본 이력 보존을 검증한다. 외부 API와 모델은 격리된 테스트 대역을 사용한다.
