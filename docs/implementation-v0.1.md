# 1차 구현 기록

작성일: 2026-09-17 · 버전: 0.1.0

이 문서는 첫 구현의 기록이다. 재사용 작업 유형·검사 실행·근거 보고서와 추가 검증은 [0.2 개선 기록](harness-improvements-v0.2.md)을 따른다.

## 세 계층

| 계층 | 코드 | 책임 |
|---|---|---|
| 하네스 정의 | `harness/jobs.json`, `harness/rules.json`, `contracts/` | 업무별 산출물·페르소나·규칙·한도·응답 스키마 |
| 작업 실행 | `src/runtime.mjs`, `src/executor.mjs`, `src/verifier.mjs`, `bin/harness.mjs` | 독립 worker, 검증·수정 루프, 실행 상태, 취소·재개, 산출물 확정 |
| 모니터링·관리 | `src/manager.mjs`, `src/manager-store.mjs`, `src/hook.mjs`, `apps/` | 이벤트 수집, 세션 투영, 업무 병합, 캘린더와 GUI |

정의는 run 생성 시 런타임 지문·규칙·스키마와 함께 실행 DB에 고정한다. 각 시도의 `process.json`에는 실제 관찰한 종료 코드·timeout·CLI 버전 등을 기록한다. 관리 서비스에는 run의 읽기 전용 투영만 저장한다. GUI의 취소·재개 요청은 관리 API를 통해 실행 서비스로 전달한다.

실행 서비스는 내구성 있는 outbox에 이벤트를 기록한다. 관리 서비스는 커서 이후의 이벤트를 읽어 자신의 DB 트랜잭션에서 이력과 커서를 함께 저장한다. 실행 서비스의 완료 판정은 관리 서비스 가용성에 의존하지 않는다.

## 데이터와 세션 규칙

`runtime.sqlite`: runs, attempts, outbox. `memory.sqlite`: work_items, agent_sessions, events, work_item_sessions, event_links, run_views, merges, cursors. `hook-state.sqlite`: turn 연결과 원본 키가 있는 훅 재전송 기록. 모든 DB는 로컬 디스크 SQLite이며 WAL을 사용한다.

원본 events는 수정하지 않는다. WIS는 같은 에이전트의 발생 시각 순으로 다시 계산할 수 있는 투영이다. 최초 입력 이벤트에서 안정적인 WIS ID를 만들고, 지연 이벤트 때문에 경계가 바뀌면 이전 투영은 비활성 상태로 보존한다. 처음부터 출력이 없으면 기존 윈도우를 유지한다. 출력이 있었고 그 이후의 모든 입력이 마지막 출력보다 20분 이상 늦다면 각각 새 윈도우가 될 수 있다.

출력은 turn으로 원래 입력에 연결한다. 어느 입력의 응답인지 불명확하면 `unresolved`로 보관하고 경계 계산에서 제외한다. 본문 없는 Stop은 관측된 시각만 보존하고 본문 누락을 표시한다. 실제 출력이 없는 실행에 종료 시각을 만들어 넣지 않는다. 실패·취소는 관측한 별도 사건으로 남긴다.

Worker의 입출력은 executor를 기준으로 기록한다. 내부 worker의 훅은 같은 시도의 생명주기·도구 이력만 보완하므로 동일 프롬프트가 중복되지 않는다. 부모 turn으로 연결하되 새 사용자 업무나 WIS를 만들지 않는다.

원본 에이전트 origin을 전달한 위임 실행은 사용자 input/output을 다시 생성하지 않는다. 해당 입출력은 실제 시스템 훅에서 받으며, worker 완료를 원본 에이전트의 Stop으로 간주하지 않는다. 하네스 자체 CLI 진입에만 실행기가 요청·결과 입출력을 기록한다. worker의 시도 ID와 CLI가 제공한 원본 세션 ID·사용량은 별도로 보존하고 제공되지 않은 값은 추정하지 않는다.

병합은 기존 업무의 `merged_into` 연결을 같은 트랜잭션에서 변경한다. 원래 업무 소속·이벤트·WIS·run ID는 보존한다. 시간 경계 계산에는 원래 소속을 사용하므로 병합이 과거 세션을 재분할하거나 합치지 않는다. 요청 ID는 재전송에, 버전 번호는 제목·설명의 오래된 덮어쓰기 방지에 사용한다.

## 로컬 API

서비스는 loopback 주소에만 listen한다. 각 데이터 디렉터리에 0600 권한으로 만든 토큰을 인증에 사용하고 Host/Origin을 검사한다. GUI는 직접 DB를 수정하지 않는다.

| 소유 서비스 | API | 용도 |
|---|---|---|
| 실행 | `POST /runs` | 자연어 prompt와 선택적 업무/입력/원본 문맥으로 실행 생성 |
| 실행 | `GET /runs`, `GET /runs/:id` | 실행 및 시도 조회 |
| 실행 | `POST /runs/:id/cancel`, `/resume` | 실제 실행 제어 |
| 실행 | `GET /events?after=N` | 내구성 이벤트 outbox |
| 관리 | `POST /api/events` | 정규화 이벤트 배치 수집 |
| 관리 | `GET /api/items?q=…`, `GET /api/items/:id` | 업무 검색, 별칭·세션·이력·run 조회 |
| 관리 | `PATCH /api/items/:id` | version을 사용한 제목·설명 편집 |
| 관리 | `POST /api/merge` | ids, target, operation_id로 병합 |
| 관리 | `GET /api/calendar?start=…&end=…&mode=sessions\|items` | UTC 시간 구간과 출처 조회 |
| 관리 | `GET /api/artifacts/:run-id` | 완료 산출물 경로·해시 대조 후 내용 조회 |
| 관리 | `POST /api/runs/:id/cancel`, `/resume` | 실행 서비스로 명령 전달 |

캘린더 API의 업무 모드는 겹치는 구간을 합집합으로 묶고 공백은 유지한다. 월 보기만 같은 업무·날짜의 여러 구간을 한 항목으로 요약한다. 실제 세션 데이터는 변경하지 않는다. UI는 원본 UTC 시각, 현지 날짜 경계, DST offset을 보존한다. 일·주 보기의 반복되는 현지 시각은 같은 시간대 위치에 놓이고 상세 tooltip에서 offset을 구분한다. 각 보기에서 숨긴 항목 수와 더보기 목록은 같은 데이터를 사용한다.

## 복구와 완료

검토 통과는 선언만으로 처리하지 않는다. 필수 규칙별 근거, 산출물 존재·형식·범위, 검토 전후 해시를 확인한다. HTML은 실제 Chromium 페이지에서 로드하고 지정한 상호작용을 검사한다. 최종 파일은 intent → atomic 반영 → 해시 확인 → 완료 순서로 확정한다.

서비스 시작 시 running을 interrupted로 전환한다. 기존 쓰기 worker가 살아 있으면 재개를 거부한다. 게시 직후 crash한 경우에는 고정된 정의, 검토 결과, 검증 보고서, 최종 파일 해시를 대조해 추가 모델 실행 없이 완료를 복구한다. 근거가 없으면 새로운 시도 디렉터리에서 다시 실행한다.

개별 시도 기본 timeout은 180초, stdout/stderr 합계 한도는 4 MiB이다. 수정은 2회까지, 동시에 실행하는 업무는 3개까지다. 검증이 명백히 실패하면 전체 모델 검토를 건너뛰고 수정으로 이동한다. 자동 네트워크 재시도와 세밀한 비용 한도는 후속 작업이다.

## 첫 배포의 제한

이 버전은 단일 파일 산출물 흐름, 관리 UI, 로컬 기록의 작동을 검증한다. 입력 자료는 prompt와 JSON의 인라인 자료를 사용한다. 외부 첨부 파일의 자동 스냅샷 수집, 복합 DAG, 코드/Git 통합, 세부 조직 정책 결합, 자동 AI 메타데이터, 완전한 transcript 수집, 업데이트·삭제 도구, 대규모 이력 페이지네이션은 구현하지 않았다. 실제 외부 에이전트의 세션이 하네스 run에 자동 연결되려면 진입점에서 원본 문맥을 전달해야 한다. 현재는 명시적 origin 전달 또는 GUI 병합을 지원한다.

설치 패키지는 준비했지만 사용자 홈의 훅·LaunchAgent 설정을 자동 적용하지 않았다. 설치 E2E는 격리된 임시 홈에서 기존 설정 보존을 검증했다. 운영 시에는 조직의 승인된 기능과 설치한 CLI 버전에서 훅 작동을 확인해야 한다.
