# 이력 기반 제목·설명·세션 요약 재작성

작성일: 2026-09-17 · 상태: 로컬 구현

## GUI 동작

업무 상세의 **제목·설명 다시 작성**은 버튼을 누른 시점에 수집된 모든 Work Item Session의 입출력과 유효한 요약을 사용한다. 병합된 work item도 원래 에이전트·세션·날짜를 보존한 채 전체 이력을 전달한다. 원문이 바뀐 뒤 갱신되지 않은 요약은 근거에서 제외하고 원본 입출력을 사용한다.

새 기본 지시문은 제목 1줄과 Markdown 설명을 만든다. 설명은 `## 작업 배경`, `## 목적`, `## 범위`, `## 결과`의 네 절을 순서대로 포함하고 필요한 내용은 bullet으로 나눈다. 결과가 아직 없으면 미완료·미확인으로 표시하며 요청을 완료 사실로 바꾸지 않는다. 기존 일반 텍스트 설명과 직접 편집한 원문은 보존하고, 편집창은 Markdown 원문을 그대로 다룬다. 사용자가 저장한 로컬 작업 지시문을 이 기본값으로 자동 교체하지 않는다.

세션 이력의 **요약하기 / 재요약**은 종료 여부와 관계없이 해당 세션의 현재 입출력을 요약한다. 요약 제목은 시간 구간과 함께 접힌 카드에도 표시한다. 요약이 없으면 **요약하기**, 있으면 **재요약**을 표시하며 생성 중에는 **요약 중** 상태로 중복 요청을 막는다. 버튼을 눌러도 카드의 접힘 상태는 바뀌지 않는다. 새 기본 지시문은 제목 1줄과 최대 5개 bullet 항목을 요구한다. 각 항목은 `- `로 시작하는 별도 줄이며 작업·결과·미완료 사항을 간결하게 구분한다. 제목과 본문을 합친 하나의 텍스트를 세션 요약으로 보관한다. 요청 시점에 수집되지 않은 미래 출력이나 미확인 응답을 채워 넣지 않는다.

상세 화면은 제목 아래에 항목별 목록을 표시한다. 기존의 일반 텍스트 요약도 계속 읽을 수 있다. 기존 본문이 긴 단락이면 공백을 동반한 문장 끝에서 화면 표시만 분리하며 소수점·버전·URL 내부의 점과 일반적인 영문 약어는 유지한다. 문장이 5개를 넘으면 5번째 항목에 나머지를 모두 이어 표시해 내용을 버리지 않는다. 이 표시 변환은 DB 원문이나 Jira 업무 로그를 수정하지 않는다. 사용자가 저장한 작업 지시문도 자동으로 덮어쓰지 않는다.

두 작업 모두 작성 대기·작성 중·완료·실패·새 내용 확인 필요 상태와 입력을 고정한 시각을 실시간으로 표시한다. 작성 중 같은 대상의 버튼을 비활성화하고 기존 내용을 유지한다. 실패한 뒤에도 마지막 정상 결과는 남는다. 완료 후 다시 누르면 같은 이력이라도 새 실행으로 재작성할 수 있다.

편집·재작성 버튼은 해당 내용의 상단 도구 모음에 둔다. 제목·설명은 **편집 / 다시 작성**을 나란히, 세션 요약은 접힌 상태에서도 보이는 카드 제목 오른쪽에 **요약하기 / 재요약**을 배치한다. 버튼의 높이·아이콘·간격을 통일하고, 직접 편집은 무채색·재작성은 옅은 블루로 구분한다. 작성 상태와 기준 시각은 내용 아래 작은 상태 행에 표시하고 상세 시각은 툴팁과 접근성 이름으로 제공한다. 작성 중 버튼 폭을 유지하며, 키보드 조작과 동작 줄이기 설정을 지원한다.

수동 재작성은 새 결과를 반영하기 직전에 입력 해시를 다시 대조한다. 생성 중 새 입출력, 요약 변경, work item 수동 편집·병합으로 입력이 바뀌었다면 `superseded`로 기록하고 덮어쓰지 않는다. 진행 중인 세션에서 기존 요약 이후 대화가 추가되면 그 사실도 표시한다. 사용자가 명시적으로 누른 재작성은 이전에 수동 편집한 값도 대상으로 삼지만, 클릭 **이후 저장한 편집**은 버전 비교로 보호한다.

## 제목·설명 자동 갱신

기본 최초 생성 기준은 사용자 에이전트의 **유효한 응답 5개**다. 원본 사용자 세션에 연결된 출력 중 본문이 있고 입력 turn과 명확하게 연결된 응답만 센다. worker·하네스 내부 출력, 본문 누락, 연결이 불명확한 출력, 중복 수집은 제외한다. 최초 기준을 채우기 전에는 첫 요청에서 만든 임시 제목·설명을 유지한다.

응답 수는 예약 조건이며 입력을 첫 5개 응답으로 잘라내지 않는다. 자동 요청은 접수 시점의 전체 사용자 세션을 고정한다. 종료되었고 현재 원문과 일치하는 완료 요약이 있는 세션은 요약을 전달하고 원문 이벤트는 생략한다. 나머지 세션은 수집된 원본 입출력을 전달한다. 수동 재작성은 기존대로 모든 세션의 원문과 유효한 요약을 함께 전달한다.

이후에는 **요약이 확정된 서로 다른 종료 세션의 누적 수**를 기준으로 갱신한다. 기본 간격은 5개이므로 5·10·15개에서 갱신하며, 직전 재작성 이후 요약 실행 횟수를 세는 방식이 아니다. 세션은 에이전트별 20분 경계로 다음 구간이 만들어지고 이전 구간에 미응답 입력이 없을 때 종료로 확정된다. 진행 중 세션의 수동 요약은 종료 세션 수에 넣지 않는다. 기존 세션의 재요약·중복 완료 이벤트·내부 작업은 세션 수를 늘리지 않는다. 요약의 원문 해시가 현재 이력과 일치해야 유효한 요약으로 사용한다.

설정은 `initial_output_count`와 `summary_interval`이며 둘 다 기본값 5, 허용 범위는 정수 1~1,000이다. GUI의 **자동 작성 설정** 또는 관리 API에서 변경하면 SQLite에 저장되고 다음 자동 예약 검사부터 적용한다. 설정 변경이나 밀린 이력 수집으로 여러 기준점을 한 번에 지나도 과거 기준점마다 모델을 호출하지 않고 최신 자료로 한 번 예약한다.

자동 갱신은 일반 `text.rewrite` 작업으로 처리하며 기존 사용자 work item에 연결한다. 기준점은 **예약 시 소비**하므로 실패·미반영된 요청을 같은 기준에서 무한 재시도하지 않는다. 필요하면 GUI에서 명시적으로 다시 작성할 수 있고, 다음 기준점에서는 새로운 자동 갱신을 예약할 수 있다. 생성 자체가 새로운 사용자 응답이나 종료 세션으로 집계되지는 않는다.

자동 생성 중 캡처한 이력 뒤에 새 입출력이 추가되는 것은 허용하며 결과는 고정된 자료 시점을 설명한다. 캡처 구간에 늦은 이벤트가 삽입되거나 내용·세션 경계·사용한 요약·수동 편집·병합·삭제 상태가 바뀌면 결과를 폐기한다. 최초 입력을 고정하지 않고 완료 순간의 새 이력을 모델이 이미 보았다고 처리하지 않는다.

**직접 편집한 제목·설명은 자동 갱신에서 보호한다.** 자동 생성 결과는 이 보호를 켜지 않는다. 사용자가 누른 수동 재작성은 보호된 내용도 그 요청에 한해 대체할 수 있지만 이후 자동 덮어쓰기를 허용하지는 않는다. 수동 재작성은 이미 충족한 기준점도 소비해 직후 중복 자동 생성을 막는다. 생성 중 새로 저장한 편집이나 삭제·병합에 따른 대상 변경은 계속 보호한다. 상세의 `metadata_rewrite.source`는 `automatic` 또는 `manual`로 요청 출처를 구분한다.

## 하나의 등록 작업, 두 출력 형식

공통 작업은 `text.rewrite`다. GUI 요청과 자동 갱신 조건 모두 관리 서비스에서 SQLite에 고정 입력을 저장한 뒤 실행 서비스에 위임한다. 실행 서비스가 `codex exec` 또는 `claude -p`를 실행한다.

```json
{
  "task": "text.rewrite",
  "input": {
    "format": "session-summary",
    "sessions": [{
      "id": "session-example",
      "engine": "codex",
      "start_at": "2026-09-17T00:00:00.000Z",
      "end_at": "2026-09-17T00:05:00.000Z",
      "summary": null,
      "events": [
        {"kind":"input","event_at":"2026-09-17T00:00:00.000Z","text":"권한 요구를 정리해 주세요."},
        {"kind":"output","event_at":"2026-09-17T00:05:00.000Z","text":"승인과 거절의 수용 기준을 정리했습니다."}
      ]
    }]
  }
}
```

`format=work-item-metadata`는 여러 세션과 각 세션의 유효한 `summary`를 전달한다. 자동 갱신에서 유효한 종료 요약을 사용하는 세션은 `events=[]`로 원문 중복을 줄인다. `format=session-summary`는 한 세션의 원본 입출력을 전달하며 이전 요약을 반복 근거로 사용하지 않는다. 누락된 본문은 `null`로 유지한다. 내부 worker의 입출력은 생성 근거에서 제외한다.

공통 응답은 기존 `status/result`를 유지한다. 생성 worker는 `{"status":"done","result":{"file":"rewrite.json"}}`을 반환하고, 산출물 JSON에는 `title`, `description`만 담는다. `text.rewrite`와 `session.summarize`는 `create-checked` workflow의 생성 → JSON·형식 검사 → 전달을 사용한다. 새 업무 설명은 `## 작업 배경`, `## 목적`, `## 범위`, `## 결과`의 순서와 각 구역의 비어 있지 않은 본문도 코드로 검사한다. 기존 평문·수동 편집과 이전 정의로 고정된 실행은 보존한다. 정상 생성은 모델 1회이며 독립 모델 검토와 형식 실패 후 자동 모델 수정을 수행하지 않는다. 실패하면 기존 결과와 오류를 보존하고 사용자가 다시 작성할 수 있다. `REWRITE-001`의 사실 근거·요청과 완료 사실의 구분은 생성 지시 기준이며 독립적으로 검토했다고 주장하지 않는다. 관리 서비스는 완료된 산출물의 위치·해시·형식을 다시 검증한 뒤 반영한다.

새 세션 요약은 제목 1줄과 `- `로 시작하는 내용 있는 bullet 1~5줄을 코드로 검사한다. 평문 단락을 새 요약으로 생성하면 형식 실패로 종료하며 추가 모델 호출이나 게시를 하지 않는다. 이 검사는 실행에 고정된 `summary_format=session-bullets-v1` 계약에만 적용한다. 이전 계약으로 접수한 실행의 재개와 이미 보관한 평문 요약의 조회는 기존 형식을 유지한다.

세션 자동 종료 요약도 같은 `text.rewrite` 경로를 사용한다. 기존 `session.summarize` 계약은 호환성을 위해 유지하며 이전 버전에서 예약하거나 시작한 요약은 원래 실행 키와 run으로 이어서 조회한다. 생성에는 선택한 CLI의 모델 사용량이 발생한다. 세션은 원본 Claude/Codex 엔진을 따르고, work item은 가장 최근 세션의 지원 엔진을 사용하며 기본값은 Codex다. GUI에서 엔진 선택을 요구하지 않는다.

## 영속 상태와 중복 방지

`writing_requests`는 요청 식별자, 대상, 고정 입력·해시, work item 버전, 상태, run 연결, 검증 결과와 시각을 보관한다. `session_summaries`는 마지막 정상 텍스트와 해당 텍스트의 입력 해시를 별도로 유지한다. 원본 이벤트를 변경하지 않는다.

같은 `operation_id`의 재전송은 기존 요청을 반환한다. runtime 수신 직후 manager가 종료돼도 저장한 실행 키로 같은 run을 조회하며 모델 작업을 중복 생성하지 않는다. 다른 식별자로 같은 대상에 동시 요청하면 거절한다. 실행 서비스가 일시적으로 없으면 요청을 대기시키고 복구 후 처리한다. 종료된 실패 작업은 무한히 다시 예약하지 않는다.

고정된 입력에는 최대 500개 세션, 세션당 최대 2,000개 입출력 이벤트를 허용한다. 초과 자료를 조용히 잘라 요약하지 않는다. 형식·크기 한도에 걸린 자동 요약은 실패 이유를 표시하고 다른 작업의 실행은 계속한다. 대규모 이력의 단계별 축약은 후속 범위다.

내부 작업은 기존 work item의 run/worker 이력에 연결한다. 별도 사용자 work item·시간 윈도우를 만들거나 work item 자체를 완료 상태로 바꾸지 않는다.

제목·설명·세션 요약의 현재 작성 요청이 실패하면 **알림**과 메뉴 막대 빠른 패널에 표시한다. 다른 에이전트가 같은 업무를 진행 중이어도 이 실패를 숨기지 않으며, 부가 작성 실패를 업무 전체의 차단 상태로 취급하지 않는다. 새로운 재작성 요청·정상 완료는 이전 실패를 대체하며 과거 실패 이력은 보존한다. 제목·설명 직접 편집은 이전 메타데이터 버전의 실패를 해소하지만 세션 요약 실패를 해소하지 않는다. **알림 지우기**는 현재 실패의 표시만 숨기고, 새 시도가 다시 실패하면 새 알림이 생긴다. 내부 작성이 진행 중이라는 이유로 일반 업무의 현재 활동 상태를 바꾸지는 않는다.

## Jira와의 관계

진행 중인 세션의 수동 요약은 로컬에만 보관한다. 20분 경계로 세션이 종료된 뒤, 원본과 일치하는 검증된 요약이 있고 티켓이 연결돼 있으면 업무 로그를 동기화한다. 종료 세션을 재작성해 내용이 바뀌면 기존 worklog ID에 PUT으로 반영한다. 요약만 바뀌었을 때 시작 일시와 관측 시간은 유지하며 새 업무 로그를 중복 생성하지 않는다. 세션 경계가 달라져 확인이 필요한 기존 로그는 계속 자동 갱신을 차단한다.

work item의 제목·설명 자동·수동 재작성은 로컬 메타데이터를 갱신한다. 기존 Jira 이슈에는 **제목·설명 반영**에서 미리보기를 확인하고 명시적으로 요청해야 반영한다. 이후 **Jira 티켓 만들기**를 누르면 그 시점의 최신 제목·설명을 사용한다.

## API

| 요청 | 내용 |
|---|---|
| `POST /api/items/:id/metadata/regenerate` | `{operation_id, version}`. 현재 work item 버전을 확인하고 재작성 예약 |
| `POST /api/sessions/:id/summary/regenerate` | `{operation_id}`. 진행 중/종료된 세션 모두 지원 |
| `GET /api/writing/:operation_id` | 상태·고정 시각·run ID·실패 또는 미반영 사유 |
| `GET /api/items/:id` | 기존 상세와 `metadata_rewrite`, 세션별 `rewrite`, 요약의 `current` 여부 |
| `GET /api/automation/settings` | `{initial_output_count, summary_interval}` 자동 제목·설명 기준 조회 |
| `PATCH /api/automation/settings` | 같은 필드 중 변경할 값을 정수 1~1,000으로 저장. 다음 자동 예약 검사부터 적용 |

`/summary/retry`는 실패한 기존 요약의 호환 경로로 남기며 최신 입력으로 새 작업을 예약한다. 업무 요청의 `task/input`이나 모델 응답에 추적 ID를 추가하지 않는다.

## 검증

2026-09-19 자동 생성·기준 설정·알림 통합 후 전체 서비스 E2E **365개**, GUI E2E **67개**가 통과했다. 최초 출력·종료 요약의 기준 경계, 중복 제외, 설정 변경·재시작, 직접 편집 보호, 병합·삭제·세션 경계 변경, 기존 DB 마이그레이션과 입력 한도 실패를 포함한다. 새 요약은 bullet 형식을 검사하고 기존 평문·이전 작업 정의는 보존한다. 모델은 fixture subprocess를 사용했으며 실모델 호출이나 실제 Jira 쓰기는 하지 않았다. macOS 빌드와 번들 소스 일치를 확인했으며 설치본은 변경하지 않았다. 근거: `output/worklog-final-verification.json`. 아래 숫자는 이전 단계의 검증 기록이다.

요약 목록·메타데이터 구조·단일 생성 workflow 변경은 `tests/e2e/writing.test.mjs`, `tests/e2e/execution-settings.test.mjs`, `tests/e2e/atlassian.test.mjs`의 **서비스 27개**, `tests/ui/writing.spec.mjs`, `tests/ui/integrations.spec.mjs`의 **GUI 6개**가 통과했다. 기존 단락의 소수점·URL·약어와 모든 문장을 보존하고 최대 5개 목록으로 표시하며, 조회가 DB 요약과 Jira 원문을 수정하지 않는지 확인했다. 새 요약 bullet, 빈 항목 거부, 기존 평문·로컬 지시문 보존, 메타데이터 4절·결과 미확인 표시, 모델 1회 생성도 검증했다. 화면은 `output/screenshots/session-summary-list.png`에 있다. 아래 전체 검사 수와 독립 검토 기록은 최초 구현 당시의 근거다.

전체 회귀 검사 **98개(서비스·CLI·설치 79개, GUI 19개)**가 통과했다. 이번 기능에 서비스 11개와 GUI 3개 시나리오를 추가했다. `npm run verify:self`가 등록된 `checks.run → verification.report`로 실행·보고했으며 실행 중 대상 파일 변경은 없었다. macOS 앱 빌드·ad-hoc 서명·ZIP 검증과 번들 Node 22.17의 서비스 시작·훅 수집 검사도 통과했다.

실행 근거: `output/self-verification/2026-09-17T05-11-53.062Z/verification.md`, 패키지 근거: `output/package-validation.json`.

버튼 도구 모음 개선 후 GUI E2E **19개**를 다시 실행해 모두 통과했다. 키보드로 편집·재작성을 실행하고 작성 중 상태, 기존 편집 보호, 실패 후 재시도, 900px 창에서 버튼 영역과 가로 넘침을 확인했다. 앱을 다시 빌드하고 번들 GUI와 작업 파일이 일치함을 확인했다. 근거: `output/self-verification/2026-09-17T08-25-44.094Z/verification.md`. 화면: `output/screenshots/writing-controls-desktop.png`, `output/screenshots/writing-controls-compact.png`.

서비스 E2E는 실제 프로세스·API·SQLite·파일·작업 검증 단계를 통과한다. 병합된 다일·다엔진 이력, 입력 스냅샷, 같은 이력의 반복 작성, 기존 결과 보존, 수동 편집·새 입력·병합 충돌, 재시작·수신 응답 유실, 산출물 변조, 크기 제한, Jira 동일 업무 로그 갱신을 다룬다. GUI E2E는 두 버튼, 대기 상태, 실시간 결과, 재작성 중 편집 보호, 실패 후 재시도를 검증한다.

모델 응답은 fixture subprocess, Jira는 로컬 모의 서버로 검증한다. 새 작업의 실모델 문장 품질, 실제 계정 쓰기와 사용자 Keychain은 이번 검증 범위에 포함하지 않는다. 자체 검사 결과는 `output/self-verification/latest.json`, 화면은 `output/screenshots/on-demand-writing.png`에 보관하며 모두 Git 추적에서 제외한다.

## 나중에 활용할 업무 근거 보존

자동·수동 작성 지침은 확인된 역할·행동·결과·제공된 측정 근거·협업·제약을 기존 네 절 또는 최대 다섯 bullet에 담는다. 이 기록은 나중에 성과 정리나 면담 자료로 활용할 수 있다. 사용자·에이전트·협업자 기여, 목표와 관측 결과를 구분한다. 근거 없는 KPI·개선율·절감시간·평가점수는 생성하지 않는다. 자동 갱신 기준과 모델 호출 수는 유지하며 이후 작성부터 적용한다. [업무 요약](work-reports.md)은 선택한 날짜 또는 분기·반기·연간 기간의 원본과 요약을 같은 형식으로 정리한다.
