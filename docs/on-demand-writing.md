# 이력 기반 제목·설명·세션 요약 재작성

작성일: 2026-09-17 · 상태: 로컬 구현

## GUI 동작

업무 상세의 **제목·설명 다시 작성**은 버튼을 누른 시점에 수집된 모든 Work Item Session의 입출력과 유효한 요약을 사용한다. 병합된 work item도 원래 에이전트·세션·날짜를 보존한 채 전체 이력을 전달한다. 원문이 바뀐 뒤 갱신되지 않은 요약은 근거에서 제외하고 원본 입출력을 사용한다.

세션 상세의 **요약 다시 작성**은 종료 여부와 관계없이 해당 세션의 현재 입출력을 요약한다. 제목은 1줄, 설명은 최대 5줄이며, 합친 일반 텍스트를 세션 요약으로 보관한다. 요청 시점에 수집되지 않은 미래 출력이나 미확인 응답을 채워 넣지 않는다.

두 작업 모두 작성 대기·작성 중·완료·실패·새 내용 확인 필요 상태와 입력을 고정한 시각을 실시간으로 표시한다. 작성 중 같은 대상의 버튼을 비활성화하고 기존 내용을 유지한다. 실패한 뒤에도 마지막 정상 결과는 남는다. 완료 후 다시 누르면 같은 이력이라도 새 실행으로 재작성할 수 있다.

편집·재작성 버튼은 해당 내용의 상단 도구 모음에 둔다. 제목·설명은 **편집 / 다시 작성**을 나란히, 세션 요약은 카드 오른쪽에 **다시 작성**을 배치한다. 버튼의 높이·아이콘·간격을 통일하고, 직접 편집은 무채색·재작성은 옅은 블루로 구분한다. 작성 상태와 기준 시각은 내용 아래 작은 상태 행에 표시하고 상세 시각은 툴팁과 접근성 이름으로 제공한다. 작성 중 버튼 폭을 유지하며, 키보드 조작과 동작 줄이기 설정을 지원한다.

새 결과를 반영하기 직전에 입력 해시를 다시 대조한다. 생성 중 새 입출력, 요약 변경, work item 수동 편집·병합으로 입력이 바뀌었다면 `superseded`로 기록하고 덮어쓰지 않는다. 진행 중인 세션에서 기존 요약 이후 대화가 추가되면 그 사실도 표시한다. 사용자가 명시적으로 누른 재작성은 이전에 수동 편집한 값도 대상으로 삼지만, 클릭 **이후 저장한 편집**은 버전 비교로 보호한다.

## 하나의 등록 작업, 두 출력 형식

공통 작업은 `text.rewrite`다. GUI는 관리 API에 요청만 보내고, 관리 서비스가 SQLite에 고정 입력을 저장한 뒤 실행 서비스에 요청한다. 실행 서비스가 `codex exec` 또는 `claude -p`를 실행한다.

```json
{
  "task": "text.rewrite",
  "input": {
    "format": "session-summary",
    "sessions": [{
      "id": "session-example",
      "engine": "codex",
      "start_at": "2026-09-17T00:00:00.000Z",
      "end_at": "2026-09-17T00:05:00.000Z",
      "summary": null,
      "events": [
        {"kind":"input","event_at":"2026-09-17T00:00:00.000Z","text":"권한 요구를 정리해 주세요."},
        {"kind":"output","event_at":"2026-09-17T00:05:00.000Z","text":"승인과 거절의 수용 기준을 정리했습니다."}
      ]
    }]
  }
}
```

`format=work-item-metadata`는 여러 세션과 각 세션의 유효한 `summary`를 전달한다. `format=session-summary`는 한 세션의 원본 입출력을 전달하며 이전 요약을 반복 근거로 사용하지 않는다. 누락된 본문은 `null`로 유지한다. 내부 worker의 입출력은 생성 근거에서 제외한다.

공통 응답은 기존 `status/result`를 유지한다. 생성 worker는 `{"status":"done","result":{"file":"rewrite.json"}}`을 반환하고, 산출물 JSON에는 `title`, `description`만 담는다. `create-reviewed` workflow가 생성 → JSON·형식 검사 → 독립 검토 → 최대 2회 수정 → 전달을 수행한다. `REWRITE-001`은 원문과의 일치, 요청과 완료 사실의 구분, 형식별 길이를 검사한다. 관리 서비스는 완료된 산출물의 위치·해시·형식을 다시 검증한 뒤 반영한다.

세션 자동 종료 요약도 같은 `text.rewrite` 경로를 사용한다. 기존 `session.summarize` 계약은 호환성을 위해 유지하며 이전 버전에서 예약하거나 시작한 요약은 원래 실행 키와 run으로 이어서 조회한다. 생성·검토에는 선택한 CLI의 모델 사용량이 발생한다. 세션은 원본 Claude/Codex 엔진을 따르고, work item은 가장 최근 세션의 지원 엔진을 사용하며 기본값은 Codex다. GUI에서 엔진 선택을 요구하지 않는다.

## 영속 상태와 중복 방지

`writing_requests`는 요청 식별자, 대상, 고정 입력·해시, work item 버전, 상태, run 연결, 검증 결과와 시각을 보관한다. `session_summaries`는 마지막 정상 텍스트와 해당 텍스트의 입력 해시를 별도로 유지한다. 원본 이벤트를 변경하지 않는다.

같은 `operation_id`의 재전송은 기존 요청을 반환한다. runtime 수신 직후 manager가 종료돼도 저장한 실행 키로 같은 run을 조회하며 모델 작업을 중복 생성하지 않는다. 다른 식별자로 같은 대상에 동시 요청하면 거절한다. 실행 서비스가 일시적으로 없으면 요청을 대기시키고 복구 후 처리한다. 종료된 실패 작업은 무한히 다시 예약하지 않는다.

고정된 입력에는 최대 500개 세션, 세션당 최대 2,000개 입출력 이벤트를 허용한다. 초과 자료를 조용히 잘라 요약하지 않는다. 형식·크기 한도에 걸린 자동 요약은 실패 이유를 표시하고 다른 작업의 실행은 계속한다. 대규모 이력의 단계별 축약은 후속 범위다.

내부 작업은 기존 work item의 run/worker 이력에 연결한다. 별도 사용자 work item·시간 윈도우를 만들거나 work item 자체를 완료 상태로 바꾸지 않는다.

## Jira와의 관계

진행 중인 세션의 수동 요약은 로컬에만 보관한다. 20분 경계로 세션이 종료된 뒤, 원본과 일치하는 검증된 요약이 있고 티켓이 연결돼 있으면 업무 로그를 동기화한다. 종료 세션을 재작성해 내용이 바뀌면 기존 worklog ID에 PUT으로 반영한다. 요약만 바뀌었을 때 시작 일시와 관측 시간은 유지하며 새 업무 로그를 중복 생성하지 않는다. 세션 경계가 달라져 확인이 필요한 기존 로그는 계속 자동 갱신을 차단한다.

work item의 제목·설명 재작성은 로컬 메타데이터를 갱신한다. 이미 생성된 Jira 티켓의 제목·설명을 수정하는 API는 추가하지 않았다. 이후 **Jira 티켓 만들기**를 누르면 그 시점의 최신 제목·설명을 사용한다.

## API

| 요청 | 내용 |
|---|---|
| `POST /api/items/:id/metadata/regenerate` | `{operation_id, version}`. 현재 work item 버전을 확인하고 재작성 예약 |
| `POST /api/sessions/:id/summary/regenerate` | `{operation_id}`. 진행 중/종료된 세션 모두 지원 |
| `GET /api/writing/:operation_id` | 상태·고정 시각·run ID·실패 또는 미반영 사유 |
| `GET /api/items/:id` | 기존 상세와 `metadata_rewrite`, 세션별 `rewrite`, 요약의 `current` 여부 |

`/summary/retry`는 실패한 기존 요약의 호환 경로로 남기며 최신 입력으로 새 작업을 예약한다. 업무 요청의 `task/input`이나 모델 응답에 추적 ID를 추가하지 않는다.

## 검증

전체 회귀 검사 **98개(서비스·CLI·설치 79개, GUI 19개)**가 통과했다. 이번 기능에 서비스 11개와 GUI 3개 시나리오를 추가했다. `npm run verify:self`가 등록된 `checks.run → verification.report`로 실행·보고했으며 실행 중 대상 파일 변경은 없었다. macOS 앱 빌드·ad-hoc 서명·ZIP 검증과 번들 Node 22.17의 서비스 시작·훅 수집 검사도 통과했다.

실행 근거: `output/self-verification/2026-09-17T05-11-53.062Z/verification.md`, 패키지 근거: `output/package-validation.json`.

버튼 도구 모음 개선 후 GUI E2E **19개**를 다시 실행해 모두 통과했다. 키보드로 편집·재작성을 실행하고 작성 중 상태, 기존 편집 보호, 실패 후 재시도, 900px 창에서 버튼 영역과 가로 넘침을 확인했다. 앱을 다시 빌드하고 번들 GUI와 작업 파일이 일치함을 확인했다. 근거: `output/self-verification/2026-09-17T08-25-44.094Z/verification.md`. 화면: `output/screenshots/writing-controls-desktop.png`, `output/screenshots/writing-controls-compact.png`.

서비스 E2E는 실제 프로세스·API·SQLite·파일·작업 검증 단계를 통과한다. 병합된 다일·다엔진 이력, 입력 스냅샷, 같은 이력의 반복 작성, 기존 결과 보존, 수동 편집·새 입력·병합 충돌, 재시작·수신 응답 유실, 산출물 변조, 크기 제한, Jira 동일 업무 로그 갱신을 다룬다. GUI E2E는 두 버튼, 대기 상태, 실시간 결과, 재작성 중 편집 보호, 실패 후 재시도를 검증한다.

모델 응답은 fixture subprocess, Jira는 로컬 모의 서버로 검증한다. 새 작업의 실모델 문장 품질, 실제 계정 쓰기와 사용자 Keychain은 이번 검증 범위에 포함하지 않는다. 자체 검사 결과는 `output/self-verification/latest.json`, 화면은 `output/screenshots/on-demand-writing.png`에 보관하며 모두 Git 추적에서 제외한다.
