# WorkLog 디자인 규칙

공통 원본은 `apps/web/style.css`의 `:root` 토큰이다. 빠른 패널과 아이콘도 같은 토큰을 사용한다. 새 화면은 개별 픽셀·색상 값을 복제하지 않고 아래 계약을 따른다.

| 요소 | 기준 |
|---|---|
| 색상 | 무채색 표면·본문, 블루 주요 동작·선택, 위험과 주의에만 상태 색상 |
| 본문 | 14px, 행간 1.6, 시작 방향 정렬 |
| 보조/레이블 | 12px, 문장·레이블 시작 방향 정렬 |
| 조밀한 메타데이터 | 최소 10px, 본문·설명에는 사용하지 않음 |
| 간격 | 4px 배수 `--space-1…12`. 관련 요소 8px, 카드 내부 16px, 구역 사이 24px |
| 버튼·입력 | 기본 높이 40px, 컨트롤 행간 1.4. 버튼 중앙 정렬, 입력 시작 방향 정렬 |
| 조밀한 동작 | 목록·캘린더 보조 동작은 32px. 달력의 날짜·시간 좌표와 아이콘 크기는 콘텐츠 구조에 따른 별도 치수 |
| 모서리 | 작은 표시 4px, 컨트롤 6px, 카드 8px, 모달 12px |
| 모달 | 내부 여백 28px, 최대 높이 화면의 90%, 모달 단위 세로 스크롤 |
| 연결 설정 | 최소 높이 640px, 작은 창에서는 화면의 90%로 제한. 에이전트·Atlassian을 같은 계층의 탭으로 제공 |
| 폼 | 레이블 → 필드 → 도움말 순서. 도움말 간격 8px. 비밀번호와 보기 버튼은 같은 높이 |
| 카드 | 제목·상태는 기준선 정렬, 동작 영역은 하단 정렬 |
| 탭 | 같은 높이, 중앙 정렬, 선택 색상과 하단 선. 좌우/Home/End 키 탐색 |
| 상태 | hover, disabled, focus-visible을 구분. 비활성도 읽을 수 있는 명암 유지 |
| 원문·문서 | 제목·본문·리스트는 시작 방향 정렬. 코드·다이어그램·날짜의 기능적 정렬은 유지 |

Atlassian 설정 폼은 탭 전환과 에이전트 상태 새로고침에도 유지한다. OAuth·네트워크는 세부 탭 없이 제목과 구분선으로 나눈다. 각 항목의 미저장 값은 사용자가 모달을 닫기 전까지 보존하며, 모달 종료 시 비밀값을 지운다.

## 변경 검증

- 일반 창·작은 높이에서 가로 넘침, 잘린 글자, 조작 불가능한 버튼이 없는지 확인한다.
- 연결 탭, 자격증명 마스킹/저장, 키보드 탐색, 목록/캘린더, 빠른 패널 시나리오를 실행한다.
- `npm run check:design`으로 토큰 참조와 컴포넌트 색상·글자 크기를 검사한다.
- 토큰은 `var()`로 참조한다. 선 두께·아이콘 형상·캘린더 위치·백분율·반응형 기준은 디자인 간격 토큰과 구분한다.
- 정렬은 컴포넌트 역할에 따른다. 모든 텍스트를 일괄 중앙 정렬하거나 모든 요소를 동일한 크기로 만들지 않는다.

## 설정 문구

- 안내는 사용자의 행동과 결과를 설명하는 1~2개 짧은 문장으로 쓴다.
- 구현 용어(워커·훅·backend)는 일반 안내에서 피한다. 필요하면 진단 도움말에 둔다.
- 레이블에 적힌 내용을 도움말에서 반복하지 않는다.
- 저장 적용 시점, 기존 데이터 보존, 연결 권한·비밀값 처리처럼 선택에 필요한 의미는 생략하지 않는다.
- 작업 지시문·오류 원문·사용자 데이터는 UI 문구 정리 때문에 잘라내거나 바꾸지 않는다.

## 설정 로딩

- 최초 조회와 명시적 새로고침은 해당 탭 또는 모달에 공통 로딩 오버레이를 표시한다.
- 덮인 영역은 마우스·키보드 입력을 차단하고, 닫기는 유지한다. 탭별 로딩은 다른 탭으로 이동할 수 있다.
- 실패하면 오버레이를 해제하고 오류와 재시도를 제공한다. 닫힌 화면의 응답은 새 화면에 적용하지 않는다.
- 백그라운드 상태 폴링은 입력을 차단하지 않는다. 로딩 애니메이션은 모션 감소 설정을 따른다.
