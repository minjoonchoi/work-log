## 검증 시나리오

### 기록과 업무 관리

- 마지막 출력과 입력 사이 19분 59.999초는 유지하고 정확히 20분이면 분리한다.
- 여러 날짜·여러 에이전트 세션을 병합해도 WIS ID와 시각이 유지된다. 다른 에이전트의 출력은 20분 비교 기준이 아니다.
- 병합 요청의 동시 호출과 재전송이 중복 병합을 만들지 않는다. 이전 업무 ID 및 후속 이벤트는 대표 업무로 연결된다.
- 늦게 도착한 출력으로 시간 윈도우를 재계산하고, 겹친 turn의 응답은 원래 입력에 연결한다.
- 본문 없는 Stop, 연결 불명확한 출력, 최초 출력 전 여러 입력을 구분한다. 동일 문구의 다른 입력을 삭제하지 않는다.
- worker·메타데이터 이력은 부모에 연결하고 새 사용자 업무나 시간 구간을 만들지 않는다.
- 원본 prompt 훅 → 하네스 위임 → worker 결과 → 원본 Stop 흐름에서 실제 사용자 입출력은 한 쌍만 남긴다. 내부 작업 완료를 원본 에이전트의 응답으로 만들어 넣지 않는다.
- 관리 서비스가 꺼져 있어도 훅 subprocess가 스풀에 기록한다. 복구·재전송 후 중복 없이 수집하고 원래 관찰 시각을 유지한다.
- Claude 형태의 turn ID 없는 중첩 입력은 대응을 추측하지 않는다.
- 오래된 제목 편집을 거부하고 수동 편집을 보존한다. 잘못된 배치 수집은 트랜잭션 전체를 취소한다.
- API 무인증 접근을 거부한다. 동일 원본 키에 다른 내용이 들어오면 기존 근거를 덮어쓰지 않는다.

### 실행과 복구

- CLI 프롬프트 한 번으로 GUI 없이 생성·검증·검토·수정·재검증·게시까지 완료하고 최종 JSON 하나를 반환한다.
- 각 생성·검토·수정은 다른 PID/디렉터리에서 실행된다. 검토가 요구한 거절 상태 수정이 최종 산출물에 반영된다.
- HTML 버튼이 요구한 문구를 표시하는지 실제 브라우저에서 확인하고 스크린샷 증거를 남긴다. 고장 난 버튼은 통과하지 않는다.
- 잘린 JSON, 허용되지 않은 결과 조합, 필수 규칙 근거 누락, 검토자의 파일 변경, 비정상 종료, stderr 폭주를 실패로 처리한다.
- 필수 구성 누락과 반복되는 blocking 지적은 수정 한도 안에서 종료된다.
- GUI·관리 서비스 종료 중에도 실행을 완료하고 outbox에서 이력을 복구한다.
- 취소는 worker와 자식 프로세스에 전파되고 늦은 반환이 취소를 완료로 바꾸지 않는다.
- timeout 후 새 시도 디렉터리에서 다시 실행한다. 실행기 crash 후 기존 worker가 살아 있으면 중복 쓰기를 차단한다.
- 최종 파일 게시 직후 강제 종료되어도 검토·검증·해시를 대조해 추가 모델 시도 없이 완료를 복구한다.
- 동시성 3 제한과 동일 서비스 중복 시작 차단을 확인한다.
- 업무 병합이 실행의 고정된 정의·상태·산출물 참조를 변경하지 않는다.
- Claude/Codex의 stdin·인자 배열·결과 추출·읽기 전용 검토·실제 원본 세션 ID/사용량 필드 추출을 프로토콜 대역으로 검증한다.

### GUI와 설치

- 업무 선택 → 다중 선택 → 대표 업무 변경 → 병합 → 이력 확인 → 이전 제목 검색.
- 일·주·월 더보기, 업무/세션 모드에 따른 개수 변경, 키보드로 숨긴 항목 접근.
- 자정에 걸친 동일 세션을 양쪽 날짜에서 표시하고, DST의 반복된 현지 시각을 UTC offset으로 구분.
- 제목을 HTML로 실행하지 않고 텍스트로 표시. 편집 후 새 입력·서비스 재시작에도 제목 유지.
- GUI 취소가 실행 서비스의 상태를 변경하고, 화면을 닫아도 후속 업무 실행 유지.
- 검증된 산출물 조회와 검증 후 외부 변경된 산출물 거부.
- 설치 dry run은 설정을 변경하지 않는다. 격리된 홈에 적용할 때 기존 회사 훅·기타 설정을 보존하고 재설치로 덮어쓰지 않는다.

## E2E 중 발견해 수정한 문제

1. macOS 임시 경로 `/var`와 실제 경로 `/private/var`를 비교하면서 정상 산출물을 거부했다. 기준 디렉터리도 realpath로 정규화했다.
2. 탐색 버튼 이름에 장식 아이콘이 포함되어 접근성 이름과 테스트·키보드 탐색의 의미가 달랐다. 아이콘을 접근성 이름에서 제외했다.
3. GUI를 다시 연 테스트 페이지에 연결 토큰이 주입되지 않았다. 새 페이지도 사용하는 context 초기화로 테스트 픽스처를 수정했다.
4. 변경이 없어도 캘린더 DOM을 주기적으로 다시 만들면서 스크롤·접근성 노드가 흔들렸다. 데이터가 바뀐 경우에 갱신하고 오래된 조회 응답을 무시한다.
5. 실제 CLI 문서 대조에서 Claude의 비대화형 쓰기에 명시적 허용 규칙이 필요함을 확인했다. 작업 파일의 `Edit(./파일)`만 허용하고 검토 단계는 Read만 제공한다.
6. 원본 에이전트의 요청을 하네스에 위임할 때 훅과 실행기가 같은 사용자 입력을 중복 기록할 수 있었다. 원본 origin이 있으면 사용자 입출력은 훅이 소유하고 실행기는 작업 상태와 worker 결과만 기록하도록 수정했다.

## 남은 검증

`scripts/live-smoke.mjs`는 PRD·목업·엔티티의 실제 엔진 검증을 준비한 스크립트다. 승인 환경 변수 없이 호출하면 중단한다. 실제 호출 시 결과·시도·검증 근거를 `output/live/`에 보관한다.

회사에서 허용된 환경의 실제 훅 등록, Codex App의 훅·경로 가시성, 로그인 이후 LaunchAgent 자동 시작, Apple 공증과 다른 macOS 버전은 후속 설치 검증 범위다. 설계 문서의 EVAL-001~055 전체를 완료한 것으로 표시하지 않는다.
