# 작업 유형별 실행과 반복 기준

이 표는 현재 기본 카탈로그 70개를 대상으로 한다. 기본 workflow는 독립 검토 56개, 생성 1회와 코드 검사 12개, 로컬 실행 2개다. worker 방식은 직접 응답 15개, 파일·도구 53개, 로컬 실행 2개다. 정상 호출은 수정 지적이 없는 새 실행의 모델 subprocess 수이며, 모델 제공자 내부 요청 수를 뜻하지 않는다. 최대 호출은 기본 workflow의 생성·독립 검토와 허용된 수정·재검토 예산이다. 재개하거나 실패를 기록하는 것이 완료된 산출물을 처음부터 다시 작성할 근거는 아니다.

## 검토와 worker 실행 방식을 분리

- **일반 문서·텍스트·사실 요약:** `document.*` 4종·`text.generate`·회의/진행 요약은 요청 결과 생성 1회 → 코드 검증 → 저장으로 끝난다. GUI 기록 작업도 같은 단일 생성 경로다. 형식 실패를 숨기는 자동 재작성은 없다. 사용자 문서·텍스트·사실 요약에 결과물의 독립 품질 검토를 추가로 요청하면 검토 단계를 추가한다.
- **독립 검토가 필요한 기록:** 결정 기록, 상태 보고, 인수인계는 생성과 독립 검토 각각 도구 없는 직접 응답으로 실행한다. 생성은 전체 본문, 검토는 고정된 본문과 원본 자료를 비교한 evaluations/issues만 반환한다. 수정은 등록된 지적과 고정된 기존 본문을 입력받아 새 전체 본문을 한 번 반환한다.
- **도구를 사용하는 전문 작업:** 조사, 브라우저 목업, 코드, 모델·설계 등은 기존 도구 프로필과 검증·검토 기준을 유지한다. 필요한 자료·도구가 없는 문서 작업을 이 범위로 조용히 확대하지 않는다.
- **로컬 검사:** 등록 명령 실행과 검사 근거 보고서는 모델을 호출하지 않는다.

`harness/jobs.json`의 신뢰된 `worker_mode: direct`는 도구 없는 실행 방식만 지정한다. `workflow`의 독립 검토와 수정 예산은 바꾸지 않는다. 로컬 지시문 편집으로 이 실행 계약이나 필수 규칙을 약화할 수 없다. 사용자 등록 유형은 선택한 템플릿의 실행 방식·검토 계약을 상속한다. 이미 접수한 실행은 당시 고정된 정의와 모델 설정을 유지한다.

직접 실행은 파일·스킬·명령·하위 에이전트를 호출하지 않고 입력 본문과 읽기 전용 스냅샷의 내용을 프롬프트에서 받는다. worker 작업 공간은 비어 있으며 파일 저장, 형식 검사, 해시 기록은 서비스가 수행한다. 직접 검토에도 원본 입력·후보 본문·기존 코드 검증 근거를 전달하고 모든 필수 규칙의 근거를 검사한다. 모델 검토가 필요한 문서가 한 번의 생성만으로 완료되는 것은 아니다.

`document.review`의 본 업무는 원본을 검토하고 지적 보고서를 작성하는 한 번의 실행이다. 보고서에 대한 후속 품질 검토는 기본으로 추가하지 않는다. 그 품질 검토를 별도로 요청했거나 전문 검토 유형에 필수 게이트가 있는 경우, 후속 검토자는 이미 작성된 보고서의 근거·판정·필수 기준 누락만 확인한다. 원래 대상의 전체 감사를 다시 작성하거나 원본을 수정하지 않는다. 요청 스킬은 별도 산출물로 요청되지 않은 plan/review/repair 단계를 추가로 예약하지 않는다.

`document.*` 4종·`text.generate`·`meeting.summarize`·`progress.summarize`는 기본 1회이며 결과물의 독립 품질 검토를 명시적으로 추가하면 정상 2회·수정 포함 최대 6회다. 이 템플릿에서 만든 사용자 유형도 같은 선택 정책을 상속한다. `document.review`에 원본 검토를 요청한 것만으로 보고서의 추가 품질 검토를 선택하지 않는다. 다른 전문 유형의 필수 검토를 일반 문서·텍스트라는 이름으로 우회하지 않는다. 내부 `text.rewrite` 등 GUI 텍스트 업무는 고정된 단일 생성 계약을 유지한다.

`work.report.create`의 1회는 부분 작업 기준이다. 선택 이력이 한 번에 들어오면 그대로 완료한다. 입력 120KiB 또는 100세션을 초과하면 서로 다른 부분 요약을 생성하고 검증된 결과를 통합한다. 하나만 남은 부분은 모델 없이 다음 단계로 전달한다. 부분 생성·통합 횟수는 품질 수정이나 재시도 횟수와 구분한다.

## 시간과 측정

새 실행의 모델 worker timeout 기본값은 **1시간(3,600,000ms)**이다. 입력 규모·고정된 검토 규칙을 보존하면서 정상 생성·검토를 3분에 일괄 중단하지 않도록 한다. 이 값은 전체 업무의 예상 소요 시간이나 모델 호출 횟수를 뜻하지 않는다. 취소, worker 도구 상한, 수정 횟수, 프로토콜 오류 처리는 계속 적용된다. 기존 실행 정의와 사용자가 저장한 모델·effort 설정을 덮어쓰지 않는다.

Codex 기본 모델과 effort는 `gpt-5.6-luna / high`이다. 모델·effort의 실제 선택과 override는 [모델 실행 프로필](execution-profiles.md)을 따른다. Claude에는 CLI의 모델 턴 한도를 전달한다. Codex exec JSONL은 내부 모델 요청 횟수를 제공하지 않으므로 `max_model_turns`를 내부 호출 수의 검증된 실측치나 집행된 상한으로 주장하지 않는다. `process.json`의 subprocess 시간, 첫 출력 시각, 관측 도구 수, CLI에서 확인 가능한 턴과 정책 집행 범위를 구분해서 본다.

`tests/e2e/document-single-pass.test.mjs`는 기본 문서·텍스트 생성 1회와 코드 검사 정책을 검증한다. `tests/e2e/stage-worker-policy.test.mjs`는 실제 로컬 런타임과 CLI 프로토콜 대역으로 명시적으로 추가한 독립 검토, 도구 없는 입력 전달, 전문 업무의 필수 검토 누락 차단, 등록 지적 후에만 수행하는 수정·재검토를 검증한다. 이 테스트는 실제 모델 응답 시간이나 의미 품질의 측정을 대신하지 않는다.
