# 업무 요약

로컬 이력에서 업무 요약을 작성하고 보관한다. Jira·Confluence 연결 없이 생성·탐색할 수 있으며 Confluence 게시는 완료본을 확인한 뒤 별도로 실행한다.

화면과 안내의 기능명을 ‘업무 요약’으로 통일한다. 내부 작업 ID `work.report.create`, `/api/reports` API와 파일 경로는 호환을 위해 유지한다. 기존에 저장한 제목·본문과 사용자가 편집한 로컬 지시문은 바꾸지 않는다.

## 날짜와 기간

캘린더 주·월 보기의 날짜 체크박스로 하루 이상 선택한다. 보기·기간 이동 후에도 선택을 보존하고 화면 밖 날짜는 선택 목록과 전체 해제로 확인한다. 선택 기준은 GUI 현지 시간대에서 **세션이 시작한 날짜**다. 자정을 넘긴 세션은 시작일에 한 번만 포함한다. 월 보기의 생략·업무별 묶음과 무관하게 서비스가 원본 세션을 선택한다.

**업무 요약 → 기간 업무 요약**에서 연도와 분기·반기·연간을 선택한다. 분기는 1~3·4~6·7~9·10~12월, 반기는 1~6·7~12월이며 윤년을 반영한다. 별도 회계연도 규칙은 적용하지 않는다. 날짜 선택과 기간 선택 모두 같은 업무 요약 형식을 사용한다.

자료가 없는 기간은 생성하지 않는다. 내부 worker·휴지통 업무를 새 업무 요약에서 제외한다. 진행 중인 세션은 캡처 시점까지 포함하되 미응답·미완료를 구분한다. 업무·태그·Jira 참조·세션·유효한 세션 요약 또는 입출력을 고정하고 **생성 시각 내림차순**으로 조회한다. 이후 원본 편집·병합·삭제로 업무 요약을 바꾸지 않는다. 같은 기간 재작성은 기존 업무 요약의 시간대를 유지한 새 결과를 만든다. 이전 형식으로 완료된 업무 요약도 원문을 보존한다.

## 자동 기록과 성과 근거

기존 `session.summarize`와 `text.rewrite`는 나중에 성과 정리나 면담 자료로 활용할 수 있도록 확인된 역할·행동·결과·근거를 남긴다. 자동 실행 기준, 제목·설명의 네 절, 세션 제목과 최대 다섯 bullet, 단일 생성 호출은 유지한다. 기존 기록을 일괄 생성하지 않으며 다음 자동 작성·명시적 재작성부터 적용한다.

| 관점 | 보존할 근거 |
|---|---|
| 목표와 역할 | 문제·목적과 확인된 담당 범위 |
| 실제 기여 | 사용자·에이전트·협업자의 행동 구분 |
| 결과와 산출물 | 실제 수행·검증 결과와 파일·이슈·검사 참조 |
| 수치와 영향 | 제공된 측정값·기간·범위. 목표와 관측 결과 구분 |
| 협업과 제약 | 확인된 지원·문제 해결·한계·미완료·후속 과제 |

요청을 완료 사실로 바꾸거나 미제공 KPI·개선율·절감 시간을 만들지 않는다. 팀 성과를 근거 없이 개인 기여로 쓰거나 평가 등급을 확정하지 않는다.

업무 요약은 `업무 개요`, `수행 내용`, `미완료·확인 사항`의 세 절을 사용한다. 본문은 업무와 연결된 Jira 이슈를 설명하며 세션·부분 요약 참조 목록을 나열하지 않는다. 태그와 입출력 관측 시간은 분류·활동의 근거이며 성과 점수나 실투입 시간으로 변환하지 않는다.

## 독자가 이해할 수 있는 업무별 서술

`수행 내용`은 업무 제목별로 **배경·목적 → 수행 내용·주요 판단 → 확인된 결과·산출물**이 이어지게 작성한다. 대화를 읽지 않은 독자도 왜 시작했고 어떤 일을 했으며 무엇을 확인했는지 이해할 수 있도록 문장과 목록을 사용한다. 단순 활동 나열로 끝내지 않고, 미완료·확인 사항에도 업무명을 함께 표시한다. 제공된 요약·입출력에 없는 배경이나 결과는 기록 없음·미확인으로 남긴다.

업무 제목 아래 `관련 Jira: [TEAM-123](제공된 URL)` 형태로 연결된 이슈 키를 표시한다. 입력의 모든 키와 URL을 보존하며, 연결이 없는 업무는 `Jira 미연결`로 표시한다. 같은 키라도 사이트·URL이 다르면 별개 이슈다. 병합된 업무의 관련 이슈 목록만으로 개별 세션의 담당 이슈·상태·완료를 추정하지 않는다. 원문에서 단순히 언급한 이슈와 실제 연결도 구분한다.

부분 요약을 통합할 때는 원본 세션 대신 부분 요약 본문을 받으므로, 첫 작성부터 업무 맥락·Jira 키·링크·미확인 사항을 본문에 남기고 통합 과정에서 유지하도록 지시한다. 이는 작성 지시이며 코드 검증이 Jira 키 보존이나 서술의 사실성을 보장한다는 뜻은 아니다. GUI에서 별도로 편집해 저장한 로컬 지시문은 자동으로 덮어쓰지 않는다.

## 실행과 대량 처리

`work.report.create`는 고정된 로컬 이력 또는 검증된 부분 요약만 다루는 내부 작업 유형이다. 일반 `status.report`의 신규 상태 판단·외부 자료 보고와 경계를 나눈다. 기존 실행 설정의 backend·model·effort·지시문을 적용한다. 응답은 `status/result`, 내부 산출물은 `{title,body,source_refs}` JSON이며 본문은 Markdown이다. `source_refs`는 해당 작업이 사용한 세션 또는 하위 부분의 식별자를 담는 검증 메타데이터다. 사용자 본문에는 이 참조를 삽입하지 않는다.

GUI 생성은 `create-checked`로 모델 생성과 코드 형식·근거 참조 검사를 수행한다. 별도 모델 검토는 호출하지 않으며 사실성에 대한 독립 실모델 평가를 통과했다는 의미는 아니다.

한 요청은 최대 **366개 날짜·5,000개 세션·32MiB 스냅샷**이다. 입력을 최대 100개 세션 또는 120KiB로 묶고 자료가 작으면 한 번만 생성한다. 많으면 부분 요약을 여러 단계로 통합한다. 중간 결과·의존성·실행 ID를 DB에 저장해 재시작 후 이어 확인한다. 한 자료가 한도를 넘으면 생략하지 않고 요약 또는 기간 분할을 요구한다. 사용량은 실제 부분 생성 횟수에 따른다.

각 부분의 `source_refs`와 부분 요약 의존 관계를 코드로 검사한다. 최종 원본 세션 집합이 선택 집합과 정확히 일치해야 완료한다. 본문에서 참조 목록을 제거해도 원본 스냅샷·부분 요약·누락 검증은 보존한다. 일부 실패를 전체 완료로 표시하지 않고 해당 요약의 불필요한 내부 작업만 정리한다. 원본 스냅샷은 최초 조회 후 재사용하며 상태·진행·게시 변화는 경량 상세로 조회한다. 상세의 기본적으로 접힌 원본 이력에서 고정된 세션 또는 부분 요약을 확인한다.

이전 형식의 저장 본문은 수정하지 않는다. 구버전 본문의 근거 세션 목록과 내부 참조는 화면 표시와 새 Confluence 게시 내용에서 제외하며, 원본 이력은 상세에서 계속 확인할 수 있다.

## Confluence 게시

**Confluence 게시 → 사이트·공간 선택 → 페이지 게시**로 새 페이지를 만든다. 공간 목록은 페이징을 지원한다. OAuth의 기존 페이지 읽기 외에 `read:space:confluence`, `write:page:confluence`가 필요하며 권한이 부족한 연결은 사용자가 GUI에서 다시 승인한다.

최종 요약 본문만 안전한 storage XHTML로 바꾸어 게시한다. 제목·문단·목록·강조·코드·허용된 링크와 본문에 설명된 Jira 이슈를 보존하며 임의 HTML을 실행하지 않는다. 부분 요약·세션 목록·원본 입출력의 자동 부록은 추가하지 않는다. 원본 근거는 로컬 상세의 접힌 이력에서 확인하며 게시 본문은 최대 8MiB다. 이미 게시된 원격 페이지는 자동으로 수정하지 않는다.

같은 업무 요약을 동일 사이트·공간에 이미 게시했거나 결과가 미확인이면 중복 POST를 하지 않는다. 확정된 실패만 명시적인 새 요청으로 재시도한다. 응답 유실·전송 중 종료는 `unknown`이다. 사용자가 입력한 페이지 ID의 공간·제목·본문 해시를 대조해 연결한다. 서버의 본문 정규화로 해시가 달라지면 미확인을 유지한다. 일치하는 페이지 연결이 이전 요청의 생성 성공을 증명하는 것은 아니다.

공식 [페이지 API](https://developer.atlassian.com/cloud/confluence/rest/v2/api-group-page/)와 [공간 API](https://developer.atlassian.com/cloud/confluence/rest/v2/api-group-space/)를 사용한다. 실제 테넌트 권한·서식은 모의 API 검증과 구분한다.

## API와 검증

| API | 역할 |
|---|---|
| `POST /api/reports` | `{operation_id,dates,timezone}` 작성 요청 |
| `GET /api/reports` | 생성일 최신순 목록·상태·진행 수·게시 revision |
| `GET /api/reports/:id` | 본문·고정 세션·부분 기록·게시 이력. `?view=summary`는 고정 세션 원문 생략 |
| `GET /api/reports/:id/parts/:partId` | 해당 업무 요약의 부분 본문·근거 관계 |
| `GET /api/integrations/atlassian/confluence-spaces` | `cloud_id`, 선택적 `cursor`로 공간 조회 |
| `POST /api/reports/:id/publish` | `{operation_id,cloud_id,space_id}`로 게시 |
| `POST /api/reports/:id/publications/:operationId/resolve` | `{page_id}`로 미확인 게시 대조 |

작성 요청의 선택적 `report_type`은 기존 호출과의 호환을 위해 `work`만 허용하며 기본값도 `work`다.

서비스 E2E는 `work-reports.test.mjs`, `performance-context.test.mjs`, `confluence-reports.test.mjs`, GUI E2E는 `tests/ui/work-reports.spec.mjs`에 있다. 날짜·자정·DST·병합·고정 근거·연간 다중 부분·복구·실패·명시적 게시·중복 방지를 검증한다. 일반 E2E는 격리된 모델·REST 대역을 사용하며 실모델·실계정 호출을 하지 않는다.
